# Excel 创建与保真编辑

公式重算使用Aether内置 `office_document operation="recalculate"`，传入同文件最新 `expectedHash`。不调用WPS、Office COM或外部程序。XLSX在Aether资源预览查看；没有原格式导出证据不能称为已导出PDF。

## 数据、类型与公式

先按任务确定 sheet、列头和已有数据。编号/手机号/编码为文本，保留前导零；金额/数量为数值；比例使用小数（0.12 表示 12%）或工具支持的百分数字符串；日期列使用 ISO 日期（如 `2026-10-15`），带时间时须有时区。不编造缺失行、数量、日期或结果。模板可以空行/空值交付并说明待填信息。

需随输入变化而重算的结果使用显式对象 `{ "formula": "SUM(B2:B3)" }`。普通字符串 `"=SUM(B2:B3)"` 保持文字，不会自动执行；用户提供的文本不提升为公式。避免外部工作簿引用或自动获取网络数据。

create/edit只为同表基础聚合提供有限缓存；交付前另调用recalculate执行内置跨表引用、四则及常用函数计算。该操作保留公式和其他ZIP部件，更新真实计算缓存；不支持的函数、循环、共享/数组公式或外链会拒绝整次发布并保留原文件。不能把空缓存当0，不能用硬编码数字替代公式假冒重算；重算成功后inspect读取目标值并独立核对业务口径。参数示例：`{"operation":"recalculate","path":"交付/进展统计.xlsx","expectedHash":"同文件最近返回的sha256"}`。

内置重算是有明确边界的公式域：支持跨表数字引用、四则、数字比较，以及 SUM/AVERAGE/MIN/MAX/COUNT/COUNTA、数字条件 IF/IFERROR、ROUND/ABS、数字/布尔条件 AND/OR、SUMIF、DATE、TEXT。SUM/AVERAGE/MIN/MAX/COUNT 的聚合引用按 Excel 规则忽略文本和布尔；COUNTA 计入空字符串但排除真实空白。ROUND 暂拒绝以 JS 科学计数表示的数值、非整数精度、绝对值超过 15 的精度和移位后绝对值达到 1e20 的输入。SUMIF 使用明确同形范围，支持数字条件及不区分大小写的文本条件、`*`/`?`/`~`转义，非空正向文本条件允许 criteria 范围含预留空行（空行不匹配）；数值条件、空条件或否定条件与空行混用仍明确拒绝，不隐式扩大 sum_range。DATE 使用工作簿 1900/1904 基准并保留 Excel 1900 闰日规则；TEXT 支持常见数字格式及 `yyyy-mm-dd`/`yyyy/m/d`（可带 `hh:mm:ss`）。普通文本比较、混合类型算术、TRUE/FALSE 字面量、幂、连接运算符、字面量强制类型转换及未列出函数暂明确拒绝，不能把这些拒绝当验收成功。重算更新普通单元格公式缓存及支持的本地单行/单列图表引用缓存；不刷新数据透视等其他对象，命名/外部图表引用会告警；必须独立核验业务金额与日期。

## 创建工作簿

`columns.header` 始终写入工作表第 1 行，`rows` 的第一项从第 2 行开始，公式引用须按实际行号计算。用户要求精确单元格位置时，创建后用 `edit` 的 `sheet/cell/value` 定点写入目标值与公式；多余单元格用 `value: null` 清除，然后 `recalculate` 并 `inspect` 核对。发现行偏移时修正同一文件，不重复创建副本，也不绕过原生工具解包改写。

```json
{
  "operation": "create",
  "path": "交付/进展统计.xlsx",
  "expectedHash": "missing",
  "workbook": { "sheets": [{
    "name": "项目进展",
    "columns": [
      { "header": "事项", "key": "item", "type": "text", "width": 24 },
      { "header": "工时", "key": "hours", "type": "number" },
      { "header": "完成率", "key": "progress", "type": "percent" },
      { "header": "计划日期", "key": "date", "type": "date" }
    ],
    "rows": [
      { "item": "联调", "hours": 8, "progress": 1, "date": "2026-10-15" },
      { "item": "验证", "hours": 6, "progress": 0.5, "date": null },
      { "item": "合计", "hours": { "formula": "SUM(B2:B3)" }, "progress": null, "date": null }
    ],
    "charts": [{ "type": "column", "title": "工时安排", "categoryKey": "item", "series": [{ "key": "hours" }], "endRow": 3 }]
  }] }
}
```

这是 API 用法示例，数字不是可复用的业务事实。`columns.key` 对应每行对象字段，sheet 名及列 key 唯一，不允许漏定义列。工具提供冻结首行、表头样式、筛选、数字格式、列宽、打印设置和原生图表；要在读取实际输出后才描述最终效果。

`charts` 可用于 create/append_sheets，每表最多8个，支持 column/bar/line/area/pie/doughnut/scatter。`categoryKey` 和 `series[].key` 引用本表列，不重复抄数据；默认取第2行到末行，`startRow/endRow` 是Excel真实行号，最多1000点，汇总行不应混入分类时显式排除。每图最多8系列，饼图/环形图只取1系列且非负；散点图categoryKey须为数值X坐标。可选series.name/color、legend和anchor `{cell:"F2",width:640,height:360}`；未指定位置时排在数据右侧。图表为可编辑原生对象并引用单元格，空值保留缺口，未重算公式不会伪填0。修改支持的本地引用数据后会同步图表缓存；命名范围/外部链接/复杂引用保留原缓存并由inspect告警，不能宣称这些图表已更新。图表引用或类型的结构性编辑暂未提供，需要改变结构时新建修订版。

create 与 append_sheets 使用同一套内容估宽、换行估高和类型规则；普通 number 使用 General 保留有效数字，不强制补两位小数，percent 仍显示两位百分比，date 仍显示日期。金额单位和业务精度须明确核对，不能把默认格式称为定制财务格式。超长单元格估高超过 Excel 409 磅上限会明确拒绝：按实际内容加宽列或拆分到多行/文档，不删字凑布局。自动估高不是实际渲染证明，交付前仍检查长文本、表头和公式结果的显示。

## 分批追加新工作表

小型多表工作簿的内容已定、能够在一次模型输出内完整提交时，用一次 create 同时创建这些表（最多12张），不把几张短表人为拆成多轮。内容较大、可能超过输出容量或向已有工作簿添加新表时，再使用 append_sheets：每批只发送新增的1–4张表，不重发旧表；每批成功后使用刚返回的新 hash。最终工作簿最多24张、100000个实际单元格，单次参数不超过2 MiB；模型输出容量可能先到上限，应按实际内容选择批次，不能为批量省略单元格。

```json
{
  "operation": "append_sheets",
  "path": "交付/进展统计.xlsx",
  "expectedHash": "使用同文件最近一次工具返回的 sha256 版本",
  "workbook": { "sheets": [{
    "name": "校验记录",
    "columns": [
      { "header": "校验项", "key": "item", "type": "text", "width": 28 },
      { "header": "实测值", "key": "actual", "type": "number" }
    ],
    "rows": [{ "item": "按任务实际校验后填写", "actual": null }]
  }] }
}
```

`edit` 提示“工作表不存在”时，不要改为 create 覆盖同一路径，也不要删除已有工作簿。应确认真实表名；确实缺表就调用 `append_sheets`。重名表会拒绝，不覆盖或合并。参数截断/解析失败先 inspect 确认哪些表已真实落盘，只重试缺失的小批次，不能把失败尝试当成已追加。

追加通过 OOXML 部件增补完成，不将原工作簿交给 ExcelJS load→save：原有 worksheet、图表、图片、结构化表、数据透视和自定义部件的解压内容保留；工作簿目录/关系/内容类型和尾部新增样式会变化，旧计算链按准确关系移除。ZIP压缩容器字节本身会变化，不称“整文件字节不变”。签名、结构锁定、共享修订或不能可靠处理的包结构会整批拒绝。

**旧公式缓存保留但未重算。** 新表可能改变 INDIRECT 等依赖，不能拿旧缓存证明最新结果；工具设置打开时完整重算，只为新表受支持的基础聚合计算缓存。交付金额/校验依赖公式时，需要实际重算并重新读回。旧扩展属性/应用统计同样保留，可能需 Office 刷新；这不等于新表在实际 workbook 目录中缺失。追加回执仍只是结构检查，视觉效果需另行打开验证。

普通已有表的新单元格可用小批 `edit`（单次最多1000项）明确写入行号；它不会替你扩展筛选/打印区域、结构化表、图表、公式范围或为新行复制样式。涉及这些结构时先明确支持边界，不能把零散新增单元格称为完整“追加数据表”操作。

## 编辑现有工作簿

先 `inspect` 获取真实 sheet/单元格结构、公式与当前 `expectedHash`，然后：

```json
{
  "operation": "edit",
  "path": "交付/进展统计.xlsx",
  "expectedHash": "使用工具刚返回的 sha256 版本",
  "edits": [
    { "sheet": "项目进展", "cell": "B2", "value": 10 },
    { "sheet": "项目进展", "cell": "B4", "value": { "formula": "SUM(B2:B3)" } }
  ]
}
```

只定点修改所列单元格，保留未修改 ZIP parts 和样式，不把整本工作簿重写当作“保留所有原始对象”。工具对数字签名、合并从属单元格、共享/数组公式区域、结构化表等不支持的目标修改会拒绝；不要解锁安全设置或删掉原结构强行完成。编辑后通过 inspect 复查目标值、依赖公式缓存和待计算 warnings。inspect 不展示相邻样式细节；工具内部保留结构不等于模型已独立验证样式，视觉检查需要实际可用的打开或渲染路径。

目前支持 `.xlsx`，CSV 可用现有读取工具取数据后明确新建 `.xlsx`；不能在同路径上悄悄改格式。大型多表按上述追加合同分批；单表数据超过实际限额时缩小任务或分文件，不用缺失行伪造完整交付。
