# Word 创作与编辑

需要 PDF 导出或视觉渲染时，先用可用的 `office_environment({})` 并读取 `references/environment.md`；原生 DOCX 结构检查不等于渲染完成。转换与 COM 操作必须有有限 `timeoutMs`，只操作本任务持有的文档。

## 结构和写作

按具体任务选择合适结构，不强制套满章节：

| 任务 | 常用结构 |
| --- | --- |
| 周报/月报 | 本期概要、重点进展、问题与风险、下期计划 |
| 会议纪要 | 会议信息、决议（负责人和期限）、讨论要点、待办 |
| 通知 | 事项、安排、要求、落款与日期 |
| 方案 | 目标与背景、方案内容、资源与排期、风险与收益 |
| 总结 | 已完成成果、有效做法、问题、改进方向 |

写具体动作与结果。材料没有数据时不用数字装饰；未知负责人、日期和指标标为“【待补充：…】”。保留用户素材中的限制条件和未解决事项。

## 创建真实文档

```json
{
  "operation": "create",
  "path": "交付/项目周报.docx",
  "expectedHash": "missing",
  "title": "项目周报",
  "author": "项目组",
  "markdown": "## 本期进展\n\n完成接口联调。\n\n| 事项 | 负责人 | 状态 |\n| --- | --- | --- |\n| 接口联调 | 【待补充】 | 已完成 |\n\n## 下期计划\n\n- 验证异常恢复。"
}
```

`title` 为可选的独立可见标题，同时写入文档属性；传入后不要在 Markdown 首行再次重复同名标题。也可不传 `title`，直接在 Markdown 中安排标题。`author` 为可选作者属性，只使用已知真实信息。Markdown 负责标题、段落、列表、简单表格与基础行内强调；不把任意 HTML、外链图片、脚本或复杂版式混入正文。工具内置中文正文字体、标题层级、行距、A4 页面、表格样式与页码。不要因默认样式而改变内容要求；特殊公文精确版式、复杂图文、修订模式等能力未提供时如实说明。

表格每列含义要明确，列数控制在可读范围，长说明放正文。正文段落保持一事一段，标题层级连续。没有真实渲染结果时只确认结构、内容与设置，不承诺“绝无跨页/截断”。

## 编辑现有 Word

先 `inspect` 获取真实正文、完整字节 `expectedHash`、结构与风险提示，再调用：

```json
{
  "operation": "edit",
  "path": "交付/项目周报.docx",
  "expectedHash": "使用工具刚返回的 sha256 版本",
  "edits": [{ "oldText": "完成接口联调。", "newText": "完成接口联调，并补齐超时恢复验证。" }]
}
```

`oldText` 必须在原文内唯一，多个编辑基于同一份原文，不依赖上一条替换的结果。只修改授权段落/单元格文本，其他 ZIP parts 保持原样。工具可跨同一段落中因样式切分的文本节点定位，替换文字继承起始文本节点的样式；跨段落、歧义、重叠、复杂字段/修订内容等无法可靠处理时会拒绝。扩大唯一上下文或缩小改动，不把全文重建当作原样保留格式。

交付核对标题和章节、表格行列、要求的修改与剩余待补充项；对保留格式和未支持复杂结构的说明以 inspect 实际警告为准。
