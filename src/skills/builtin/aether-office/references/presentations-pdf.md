# Aether 内置演示与 PDF

这些写入使用引擎自带库，不调用 WPS、Office COM、LibreOffice、Python或外部服务。文件直接在 Aether 资源预览查看。

## PPTX

### 先组织信息，再设计页面

先确定受众、用途和每页要传达的内容，再选择构图。主题页用简明主题标题，有依据的结论页才用结论标题。正文只留现场阅读所需信息；项目文件清单、运行命令和测试脚本通常放 `notes`，技术交接等受众确实需要时再展示。缺失数据明确待补，不编造数字、来源或作者。

使用 `office_document operation="create"`、`.pptx` 路径、`expectedHash="missing"` 和 `presentation:{theme,slides}`。主题字段必须放在 `presentation.theme` 内，不能平铺到 `presentation`；字段与容量遵守工具 schema。只使用一套按内容设计的流程，不增加固定模板、预设风格目录或备用模板说明。

- 产品/游戏介绍围绕用途、玩法和产品体验展开。已有相关截图、品牌图或其他真实素材时，优先展示具体画面，而非用文字复述所有细节。先定点读取 README 与已有素材目录即可，不为找配图升级成全项目扫描、测试或启动服务；没有可信素材时按事实用原生文字与图表说明，不造产品截图，不强迫每份演示使用图片。
- 每页形成清晰主次：产品画面与简短说明、关键数字与证据、对照、过程或引述，按内容选用。不要把所有内容轮流装进 `bullets`、`columns` 和 `table` 就当作设计完成；不默认同色三栏、装饰短横线、重复卡片或每页同样的标题加小块正文。留白服务于主体，不能让文字缩在一角而大片区域没有信息目的。
- 使用有来源的数据绘制原生 `chart`，确需逐项比较才用原生 `table`；表格、图表和正文保持可编辑，不用整页截图代替。表格含表头每行至少 0.58 英寸，换行另增；容量失败按回执逐项修正所需高度/列宽并检查相邻元素，不猜容量、不同时缩小高度，不为绕过失败丢掉表格或重写无关页面。说明写该页 `notes`，不向 table 添加字段。`image` 只引用已授权工作区内 PNG/JPEG，按内容选择 contain/cover，保护比例与关键信息；图片内文字不是可编辑正文。
- 构图需要自由定位时用 `custom`；原生文本、图片、图表和表格按实际 schema 组合，坐标为英寸，画布 13.333×7.5。此布局的 `title` 只作元信息，可见标题需文本元素。不要把受限的单一自动布局当作所有页面的唯一选择。

统一字体、色彩、层级、对齐和边距，保证对比。无参考时可从封面 42pt、页标题 32pt、正文 18–24pt 起步，辅助标注也须遵守 schema 最低 12pt；先删减或拆页，不能靠小字塞满内容。用户视觉参考优先；不把相似风格称为母版保真复用，当前不支持任意母版导入或动画。

### 已有文件的修订

先 inspect，再用同文件 hash 及唯一 `oldText/newText` 定点 edit；未匹配或重复文本会拒绝，其他包部件保留。`edit` 仅修改已有正文/备注文本节点，不等于可以重排版式或编辑图表数据。需要新布局时基于已核实内容新建版本，不覆盖原件，不声称重建保留了原母版和全部效果。

相同数字或文字出现在多个位置时，先用 `office_inspect` 读取 `[slide=2 textRun=7 editable=true]` 标记，再在同一项 edit 中成对提供 `slide:2,textRun:7`。编号从 1 开始：slide 是实际显示顺序，textRun 是该页所有已提取文本节点的顺序（包含不可编辑字段）。只支持 `editable=true` 的普通文本节点；`oldText` 仍须在指定节点内唯一匹配。示例：`{"operation":"edit","path":"经营评审.pptx","expectedHash":"<该文件 inspect 返回的 sha256>","edits":[{"slide":2,"textRun":7,"oldText":"127200","newText":"128400"}]}`。不得猜测编号；过期 hash、越界编号、缺少配对参数或字段节点都会拒绝且不发布。定位参数仅适用于 PPTX，不能用于 DOCX。inspect 仍是有界分页预览，需要时继续获取 `contentPage.nextOffset`。

备注也由 inspect 提取，标为 `[target=notes slide=2 textRun=1 editable=true]`；正文和备注的 textRun 各自从 1 编号。修改已有备注使用 `edits:[{"target":"notes","slide":2,"textRun":1,"oldText":"旧路径.xlsx","newText":"修订路径.xlsx"}]` 并复用同文件最新 expectedHash。省略 target 只匹配正文，不会改备注；指定 notes 不会回退匹配正文。页码等字段不可编辑，不支持新建备注部件、插入段落或跨文本段替换。不得用 shell 手改 ZIP 绕过定位与版本保护。

### 逐页看实际画面

生成后先复用同版本结构/内容回执，再调用 `workbench_render({path,page,expectedHash})` 查看 DOCX/XLSX/PPTX/PDF 的实际 Aether 画面；按返回的 `pageCount` 检查全部区段、工作表或页面，后续项沿用同一文件的 `sha256`。hash 冲突时重新确认版本，不能混合不同版本验收。

逐页检查两方面：一是裁切、溢出、重叠、对比、标签与来源是否正确；二是观众是否能迅速看懂主体、信息主次及本页目的。大片空白配一小块文字、机械重复三栏/表格、没有产品画面的产品介绍，都需结合内容重新判断并重排，不能仅因无溢出而通过。用户明确要求的极简留白可以保留，不按填满画面或固定图文比例判定。

再连看全篇，检查页面节奏、重复表达和视觉一致性，确认版式变化确实帮助理解。发现问题修正后重验受影响页；记录具体观察，不用“已渲染”代替判断。实际返回图片必须可见且已检查；截图成功、文本读回或 `structure-checked` 都不等于视觉验收。

此渲染使用 Aether 的原文件预览转换器：PPTX/DOCX 为 HTML 版面，XLSX 为 ExcelJS 表格视图，PDF 为 PDF.js 页面画面；均不保证与外部办公应用原生渲染逐像素一致。未提供 `workbench_render`、模型无视觉能力、客户端未连接或渲染失败时，明确记录“视觉验收未完成”及原因；不以另画的示意图、结构检查或自动截图成功冒充已看过成品。

## PDF

用 `create`、`.pdf` 路径、`expectedHash:"missing"` 与 `markdown` 创建，支持中文、标题、段落、列表和简单表格的分页排版。可选title/author必须来自已知信息。生成前核实实际字体覆盖全文；缺少中文字体或符号字形会明确失败，不能交付缺字/乱码，也不能擅自替换用户文字伪造成功。正文用空格缩进，不支持制表符或其他不可打印控制字符。默认只附普通页码，不加产品品牌页脚。

PDF是独立排版文件，不是从另一份DOCX/PPTX逐像素转换。PDF任意文字定点编辑尚未提供；修改时根据已核实源内容新建版本，不覆盖或假称保留旧版式。inspect/office_inspect提供实际PDF文本及页数，不证明视觉效果。交付时在Aether预览真实文件，核对分页、内容、字体和表格。

PDF 的能力范围仅覆盖独立 Markdown 排版创建和文本/页数检查：不提供 AcroForm 字段填写、任意文字定点编辑、批注/签名处理，也不把 DOCX/PPTX 转成原版式 PDF。`inspect` 成功只证明 PDF 可读取并提取了文本；没有实际页面预览或渲染检查时，必须把视觉验收标为未完成，不能用文本读回、页数或 `structure-checked` 代替画面判断。

## 验收

所有操作遵守文件版本hash和原子发布；仅成功回执才算落盘。结构检查、文本读回、视觉验证分别记录。源格式预览不保证与外部办公应用逐像素一致；不要用另绘图片冒充实际文档渲染。
