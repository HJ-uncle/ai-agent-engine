# Work 会话工具包

工具包是当前会话可选的能力集合，通过 Work 输入框的 `@ → 工具包` 选择。默认关闭，可以同时选择多个；改变选择在下一条新消息提交时生效，不改变正在运行或等待批准的任务。

| 工具包 | ID | 能力 |
| --- | --- | --- |
| Agent 管理 | `agent-management` | 查看、创建、更新、删除持久 Agent 配置，5 个工具 |
| Skill 管理 | `skill-management` | 列出、读取、创建、编辑、启停、删除项目或全局技能，6 个工具 |
| 知识库管理 | `knowledge-management` | 管理知识库及文档、导入工作区文件或文本、检索知识，11 个工具 |
| 自动化 | `automation` | 查看运行能力、列出计划、预览日程、创建、修改、暂停和删除计划，6 个工具 |
| 插件管理 | `plugin-management` | 创建、编辑、测试、发布、启停、删除和导入自定义插件，10 个工具 |
| MCP 管理 | `mcp-management` | 查看、新建、修改、启停、删除服务配置和测试连接，7 个工具 |

选择后在正文插入 `source: 'toolkit'` 标签；删除草稿中最后一个对应标签会取消该选择。发送后的标签随历史回放，能力仍按会话保存。独立的 `toolkits` 请求字段是唯一权限来源，正文标签或注释本身不授权。

回填历史消息和修改普通文字不会重新启用其中的工具包。用户在 `@` 菜单明确重新选择时启用对应能力；已有同一标签时保留一个标签。

菜单沿用单列、单行条目；选择以正文内的标签显示。删除一个包只移除该包，不清空其他选择。恢复会话选择失败时允许正常编辑文字，但暂不接受工具包增删，避免覆盖未知的已有授权。

## 目录发现

`GET /toolkits?sessionId=...&agentId=...&path=...` 返回 `{ toolkits: [{ id, name, description, toolNames, available, reason? }] }`，位于正常响应包的 `data` 内（HTTP 前缀为 `/api/v1`）。现有会话的绑定 Agent 优先于查询参数，首页可按待选 Agent 查询。白名单不足或缺少技能管理角色时显示不可用原因。Code 模式返回空列表。

前端只展示引擎实际返回且协议认识的工具包；旧引擎不支持该接口时不显示假的可用入口。Electron 的远端路由仅允许上述目录和会话选择接口的 GET 请求。

## 请求与恢复

`POST /chat` 的可选字段：

```json
{ "sessionId": "session-id", "message": "整理资料并保存复用方法", "toolkits": ["skill-management", "knowledge-management"] }
```

| `toolkits` | 行为 |
| --- | --- |
| 非空的已知 ID 数组 | 启用选中的工具包；完整工具定义在本轮首个模型请求中可用 |
| `[]` | 关闭会话的工具包授权 |
| 省略 | 沿用该租户、该会话已保存的选择；没有记录时为 `[]` |

`GET /sessions/:sessionId/toolkits` 使用当前请求的认证租户，正常响应包的 `data` 为 `{ "toolkits": ["agent-management"] }` 或 `{ "toolkits": [] }`。前端据此恢复选择。每轮公开的 `run.requestConfig.toolkits` 为该轮实际接纳的选择，私有恢复快照也保存相同字段。

仅 Work（`general`）支持启用。Code（`code`）提交非空选择返回 400；未知或重复 ID 也返回 400。工具定义顺序按目录固定，不受用户选择顺序影响。自动任务不继承交互会话的选择。

## 持久化与边界

独立的 `session_toolkits` 小表以 `(tenant_id, session_id)` 为主键，仅保存工具包 ID 数组，不保存对话、工具定义或产物。新根任务与工具包选择在同一个 admission 事务内写入；失败和重复提交不能覆盖已有选择。清除会话绑定时同步清除选择。

批准恢复使用原始已接纳任务的工具包快照，不读取新选择，也不回写会话设置；待批准操作的 `pendingAction` 冻结快照传入 `ctx.resumeToolCall`。启用能力本身不构成写操作批准。

技能、知识库和自动化写操作都接收当前任务取消信号。等待文件锁或数据库事务时被停止，取得写入权限后会重新检查；数据库提交前取消会回滚本次事务。

管理工具包的配置管理能力仅供主代理使用。执行子代理不能继承或通过 `load_tools` 加载这些管理能力；持久 Agent 配置与临时执行子代理是不同功能。选择工具包仅解除默认隐藏，不扩大绑定 Agent 或请求的 `allowedTools`。任一明确白名单缺少所需管理工具时返回 403，并列出缺少的工具。管理工具即使通过独立白名单启用，也不能越过绑定 Agent 的上限。`[]` 关闭工具包授权，但不重写独立配置的 Agent 工具白名单。

Agent 管理的公开工具固定为 `agent_list`、`agent_get`、`agent_create`、`agent_update`、`agent_delete` 五项，按固定顺序提供；扩展不能用同名实现替换工具包内置实现。旧 `agent_do_*` 不注册、不出现在目录或 `load_tools` 中；旧白名单按标准工具名合并，已保存的旧待批准调用仅在验证原始审批身份后映射执行，保留冻结操作及重复批准去重。

所有管理名称都保留给可信内置实现，未启用工具包时也禁止扩展冒用这些名称。成功的写操作带有 `metadata.resourceChange = { kind, action, id }`；前端核对成功状态与工具来源后刷新相应目录。

## MCP 管理

通过 `@ → 工具包 → MCP 管理` 启用 `mcp_server_list/get/create/update/set_enabled/delete/test`。这是内置配置管理能力，与已配置 MCP 服务提供的业务工具分开；默认不加载，Code 和子代理不可用。

支持项目层和全局层配置，操作使用精确的 `id` 与 `scope`，同名条目分别列出。工作区取自可信会话绑定，模型不能指定任意配置文件。现有 MCP 文件属于机器共享配置，本轮仅默认租户可管理；要求匹配的可信身份，本地关闭鉴权或具有 `admin` / `mcp-manager` 权限。Agent 的 MCP 绑定列表仍用于业务工具执行范围。

新建默认禁用，保存本身不启动连接。变更先展示预览并等待批准，使用文件版本检查，防止覆盖批准前的其他修改；损坏配置拒绝写入。旧配置里的凭据不会复制到模型结果或待批准快照，环境变量和请求头仅显示键名，URL、命令参数等采用脱敏显示。凭据在设置页配置，模型管理保留已有凭据。

连接测试也需批准：stdio 握手会启动进程，远程连接会发出请求。仅完成初始化和工具目录发现，不调用业务工具；沿用安全模式限制，支持取消并关闭测试连接。配置变更在之后的运行中重新发现，不改动正在执行的工具注册表。成功写入发出 `resourceChange.kind = 'mcp'`，前端刷新 MCP 目录；连接测试不产生配置变更回执。

## Skill 管理

`skill_list`、`skill_get` 和创建回执同时提供管理 `id` 和执行 `executionId`。编辑、删除使用管理 ID；Agent 或会话的 `skills` 绑定使用 `executionId`，不能把管理 hash 当成执行绑定。Agent 管理工具会拒绝当前工作区无法解析的管理 hash，并提示正确字段；合法的同形执行 ID 仍可使用。

`skill_create` 的 `content` 为 Markdown 正文，`skill_update` 提交包含原名称的完整 `SKILL.md` 和读取时的 `expectedHash`。编辑只替换主文档，保留脚本和附件；删除会冻结目录文件快照，确认前发生修改就拒绝执行。

工作区来自可信会话上下文，工具参数不能改写项目根目录。项目层与全局层分开管理；本地关闭鉴权时可管理，启用鉴权时要求 `admin` 或 `skill-manager`。非默认租户不能管理机器共享的全局技能。Windows 长短路径统一规范化，技能目录和文件路径拒绝越界及链接跳转。

HTTP 编辑接口 `PUT /skills/:name?path=...&scope=...` 使用 `{ content, expectedHash }`；GET 详情提供 hash。旧 POST 覆盖也要求版本 hash，并保留其他文件。

## 知识库管理

读取所选资料与管理配置使用不同授权。普通 Work 的结构化 `knowledgeBases` 非空时，自动提供 `knowledge_list/get/documents/document_get/search` 五个只读工具及首轮 schema，无需启用管理包。用户选择知识资源如同附加资料，能够读取选择范围，即使 Agent 的默认知识库列表或业务工具列表没有这些读取工具；它不启用任何写工具。未选择知识资料时，普通模式仍不增加这五个工具。Code 模式不因该选择增加工具。

五个读取工具使用当前租户、注册时冻结的读取范围和执行时范围的交集；绑定文档仅授权该文档，绑定库可授权库内文档。注册实现禁止外部工具冒名替换。运行时提示提供所选库/文档名称和 ID，说明引用不是文件路径，目录与分页正文读取不依赖 FTS 命中；相关目录放在请求上下文尾部，不改变稳定系统前缀。自动检索排除正文引用元数据与 slash ID。

Work 会话保留已选择的知识资源，下一轮普通追问或只选择管理工具包时仍发送相同读取范围；发送成功只消费草稿中的知识标签。恢复页面不会把已发送标签重新插入输入框，用户可在资源选择器中主动取消知识库，之后的新请求发送更新后的范围。技能与 MCP 的单条引用语义保持原有行为。

执行与调研子代理都可继承这五个可信只读工具，第一轮即可调用；知识库管理版本仍仅供主代理使用。子代理接收冻结的资源范围，续跑与当前可用范围取交集，不能凭旧委派快照恢复已经撤销的读取权限。目录展示和范围核对只查询文档元数据，不加载正文或旧文档的完整分块。

管理写操作仍同时遵守当前请求资源范围和绑定 Agent 的原始知识库上限；选择资料不能扩大修改、删除、导入的管理权限。显式空数组表示无权限，显式绑定下不能创建一个白名单外的新库。只有启用管理包而没有选择资料时，其读取工具沿用管理范围。

`knowledge_import` 接收文本或当前工作区文件，两者只能选一种。文件最多 2 MiB，提取正文最多 1 MiB；导入确认冻结 ID、内容、来源 hash 与库版本，批准时重新检查文件和权限。库/文档更新采用事务与版本冲突检测，文档变化会递增所属库版本。

`knowledge_search` 使用现有 FTS 和多语言文本匹配，不是向量检索；权限范围在结果数量限制之前过滤。

## 自动化

`cron_capabilities` 报告当前环境的真实运行能力；`cron_preview` 仅预览发生时间。支持间隔、带时区的日历以及已有 cron 规则，目标可为已有会话、独立任务或已绑定工作区。

创建、修改、暂停与删除均使用持久化审批，执行冻结配置并复核版本和目标。重复批准不会创建第二个任务，暂停/启用保留已有 `automationReceipt` 协议。删除计划保留运行历史，不停止已在执行的任务。

当前后台派发只支持本地关闭鉴权的默认租户。开启鉴权或非默认租户时，只能明确保存 `enabled: false` 的暂停配置，不能承诺自动执行；没有手动立即运行能力。错过的运行和重叠运行跳过。本轮不扩展调度器的鉴权派发支持。

`/tools` 与 `/system-tools` 展示完整可选目录，`defaultEnabled` 使用与新建 Agent 相同的运行时推荐集合，尊重对应 profile 和 OSM 默认限制；完整展示不扩大默认授权。
