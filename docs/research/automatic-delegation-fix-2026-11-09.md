# Work 深度调研未自动调用子代理

## 现场

会话 `work-home-ddf8d23e-c2a4-404e-acbe-01265dcbe472`，运行 `9431989f-708c-4f76-8c0d-10518d71d603`，用户请求“深度调研 一下这个项目”。工具记录包含 30 次调用：读取源码、代码图、命令和路径查询，子代理目录/启动/续用均为 0。代码索引修复已生效，自动协作仍未触发。

前端 Work 协作面板会合并自动 `subagent/subagent_start/subagent_followup` 工具记录及服务端按父会话查询的全部运行，不按用户 @ 选择名单过滤。默认助手不带额外工具白名单；本次没有子代理可显示，不是显示遗漏。此修复没有修改前端。

## 原因与修复

原先“优先使用子代理”位于较长的通用执行协议中；只有目录工具默认可见，创建和续用工具依赖模型先查目录或加载定义。普通自然请求没有用户选择协作者时的强制分工流程。实际模型能够跳过这个建议，持续由主代理读取整个项目。

本轮落实：

- 将早期分工规则前置：跨模块深度调研即使只交一份报告，也先读取共同入口再分派独立模块；不等主代理查完整个项目才派发。
- `subagent_start` 首次请求可见。`subagent_followup` 和 `subagent_wait` 继续按成功目录/启动回执加载，未把整套协作工具常驻。
- 增加 `buildDelegationRequestContext`：按当前请求实际可调用工具，在动态尾部给出具体分工步骤。该提示不进入静态 system 或持久化历史。
- 已明确选择协作者且提供 `collaborator_dispatch` 时使用原选择分工协议，避免重复自动创建；无创建权限、子代理或无工具收尾不提供创建指引。
- 保留相关已完成实例优先复用、用户禁止委派优先、小任务直接做、调研只读与主代理验收结果等边界。

权限与执行实现不变：可见 schema 不授予额外权限。自定义 Agent 白名单、OSM 工具限制、子代理禁止递归均保留。

## 真实模型验证

通过真实 Work HTTP 路由，使用当前配置的 `deepseek-v4.1-flash-1017`。项目为本地生成的合成订单系统，24 个 TypeScript 文件，订单、库存、定价、审计四个模块。没有复制用户真实项目给模型。资料和用户请求均不要求使用子代理。

自然提示：`深度调研一下这个项目。只读检查，最后在会话中给出结论。`

| 实验 | 结果 |
| --- | --- |
| 原策略 | 9 次模型请求，0 子代理，目录工具首轮可见但未使用 |
| 仅前置静态分工规则 | 11 次请求，0 子代理 |
| 再提供首轮启动 schema | 14 次请求，0 子代理 |
| 加入当前请求协作决策 | 主代理查目录后，启动 2 个 research 子代理；两者均 succeeded，主代理等待、读取结果后再汇总 |
| 单文件对照 | 2 次模型请求、1 次 read_file，0 子代理，计算结果 2600 正确 |

成功运行中的分工：一名负责订单/校验与路由，另一名负责库存/定价/审计。两个子代理均实际读取源码并查询已有索引；全部项目文件内容保持不变，没有创建或重建索引。父模型在两个子代理完成后确实发生了新的请求，验收不是仅凭终态数据库行推断。

证据：`.tmp/delegation-investigation-20261109/delegation-context-2026-11-09T14-02-42-800Z-4b9b2f/` 的 `evidence.json`、`delegation_research-1.json` 和 `delegation_small-1.json`。

这次合成项目的父子总计 26 次请求、320,833 输入 tokens；自动协作不等于必然减少总 tokens。此次验证证明自动分工、只读工作和收取结果链路有效，不宣称节省费用或所有模型都必然采用相同分工。

原策略基线夹具在审计导出文件中存在一处非预期换行转义错误，后续夹具已修复。基线用于确认“目录可见但没有调用”，不用于声称严格相同输入下的性能差值。各轮原始结果均保留。
