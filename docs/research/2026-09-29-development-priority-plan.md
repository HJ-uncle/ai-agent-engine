# 开发期最高收益任务安排：Agent Engine × Aether Code

日期：2026-09-29。依据：[两仓兼容调研](2026-09-29-aether-code-engine-compatibility.md)。

用户新增约束：尚未发布；开发数据可以清理；密钥可以迁移。本计划取代调研报告中“兼容历史发布版本、迁移历史业务数据优先”的实施顺序；原报告的事实与风险证据仍保留。

**推荐目标：先交付一个可靠、响应及时、能精确改代码的 Windows 本地 IDE。前七张任务卡完成即形成第一阶段成果；然后根据实际使用瓶颈决定下一张，不把 Claude 所有功能当成必须同时建设的清单。**

本轮只安排任务，未清理数据、迁移密钥或改业务代码。Windows 本地 embedded 是基于当前环境选定的首轮验收基线；remote/多平台需求出现时再扩展。

## 1. 现在可以省掉什么，保留什么

| 决策 | 安排 |
|---|---|
| 历史数据 | 一次性重建引擎开发状态，无须写旧 DB/JSONL 双读、升级/降级迁移和历史消息适配器 |
| 旧版协议 | 两仓同批改一个明确协议号；不匹配明确拒绝。当前只验“配对可用”和“错配可识别”，不做 N−1 四组合 |
| 旧兼容接口 | 迁完所有当前调用点后可同批删除；不能漏掉仍使用旧取消接口的卡片或仍需保留的内置控制台 |
| Runtime | 开发态明确 entry；打包态明确 bundled runtime。embedded 不自动 adopt 占端口进程，冲突换空闲端口 |
| 安装更新 | 暂不做 CDN/在线更新/增量包/双版本回滚；准备分发时先做当前 Windows 单个完整包 |
| 身份 | embedded 用简单实例 token，由 main 注入所有 HTTP/SSE 请求；不先建设账号、JWT 刷新、多角色后台 |
| 数据根 | 新 state 与 runtime 分离，secrets 独立；不搬历史数据也应从现在摆正目录 |
| 密钥 | 保留必要模型连接配置及凭据，做一次迁移；旧密钥无法读取时明确失败，不能静默覆盖 |
| 测试 | 每张任务卡都走当前真实消费方；只测本轮配对产物和受影响场景，不为未发布旧版本建大量兼容夹具 |

开发状态可清理，不影响对工作区源代码的保护：撤回覆盖用户修改、精确编辑错文件、批准前产生副作用仍然是第一阶段问题。清理范围限定已核实的引擎状态目录，不包含项目源码或用户其他应用目录。

密钥迁移不能只复制 ENCRYPTION_KEY 后删掉模型数据库：模型 API key 密文本身就在库里。只迁移继续使用的 provider/model/baseUrl/能力覆盖及凭据，验证新位置能读取后再清旧状态；过程不打印或导出明文凭据。会话、旧运行记录、旧变更快照、可重建索引不迁移。

## 2. 排序总表

工作量为相对等级，不是工期承诺：小=局部修复；中=一个跨仓闭环；大=执行和持久状态联动。每张卡可以拆实现提交，但完成标准始终覆盖前后端。

| ID | 任务 | 收益 | 工作量 | 依赖 |
|---|---|---|---|---|
| D0 | 固定配对运行时、干净状态根与最小身份 | 确认测试/开发真的使用新引擎，减少“改了没生效”和后续返工 | 中 | 无 |
| D1 | 高收益局部修复包 | 修掉配置丢失、摘要丢失、诊断卡住和权限显示竞态 | 小～中；可拆并行 | 不依赖完整 D0；合并验收用 D0 |
| D2 | 文件回退正确性与版本检查 | 避免开发者代码被错误撤回，为精确编辑建立共同基础 | 中 | D0；无需等 D3 |
| D3 | 根运行身份、工具终态、审批与等待一次贯通 | 消除删错轮次、假成功、批准不执行、重启后提问消失 | 大；第一阶段主任务 | D0 |
| D4 | 当前轮快照与游标恢复 | 解决刷新/断线缺帧和重复显示，复用已有 StreamBus | 中 | D3 |
| D5 | 真正文流式、可用 fallback 与上下文边界 | 直接改善等待体验和长任务完成能力 | 中 | D3/D4；D1 的摘要修复 |
| D6 | 精确 edit 工具 | 提高改代码成功率，减少整文件重写与输出量 | 中 | D2；使用 D3 的统一工具事件 |
| D7 | Agent 后台命令与可取消句柄 | 测试、构建和长命令不必一直占住聊天调用 | 中～大 | D3；按实际长命令需求启用 |
| D8 | 已有 LSP/Problems 的完整消费 | 编辑器语义操作与诊断展示一致 | 中 | D1；发现语言服务是主要瓶颈时优先 |
| D9 | Windows 干净环境分发包 | 离开当前开发机仍能运行 | 中 | 准备给其他人使用前，覆盖已交付 D0–D6 |

**第一阶段提交范围：D0–D6。** D7–D9 有清楚触发条件；不为了任务表全部打勾自动扩范围。准备马上给其他人试用时，D9 提到 D0–D6 完成后的第一位。

## 3. 第一阶段任务卡

### D0 — 一个确定的引擎、一套当前协议

引擎：构建时生成不依赖 cwd 的 build/protocol 元信息；最小握手只需识别构建、协议号、code profile 与当前子代理 schema。build 标识能区分未提交源码构建，不能只用 package.version。

前端：显式开发 entry 优先，移除自动 adopt 与旧 SDK 副本隐式兜底；自己启动自己管理，端口冲突换端口。ready 验实际协议/构建/实例，不只看 HTTP200。start 后立刻 stop，不允许旧 readiness 请求把状态重新改为 ready。

数据：新建稳定 state 与 secrets 目录、迁移最少模型配置和密钥、显式重建旧开发状态。保持“已有加密密钥暂不可用就报错且保留文件”。不写复杂历史迁移器，不在每次启动时自动清数据。

身份：本机 spawn 生成实例 token，main 集中为普通 HTTP、POST SSE、GET 恢复和取消加凭据，E 验证缺失/错误凭据。renderer 不持有明文 token。remote 暂不扩为完整产品；不满足文件空间/身份条件的功能明确不可用，不能静默拿本地路径执行到另一台主机。

验收：预占默认端口不会接上旧引擎；root/dist cwd 元信息一致；错协议/假HTTP200不显示 ready；缺token/错token被拒，正确token贯通HTTP/SSE/取消；重建runtime不碰新state/secrets；测试明确记录实际entry/build。

主要位置：E `src/api/http/routes/metrics.ts`、`src/auth/`；F `src/main/engine/{runtime,host,client,secrets}.ts`、`sdk/process-manager.ts`。

### D1 — 独立小修先兑现收益

四组可分配给不同模块负责人，避免做成一次大重构：

1. **模型配置无损更新**：区分 resolved capabilities 与人工 overrides；F 保存显示名时不重写能力，省略/null/false语义明确。只改一个开关也不能覆盖其他 override。
2. **摘要与能力声明正确**：修 Anthropic/Ollama 历史摘要过滤；adapter 未实现的工具/视觉能力不宣称已支持。当前常用 provider 先验收，不以补齐所有供应商为门槛。
3. **诊断限流闭合**：消除 code_diagnose 同一并发池重复占用；unsupported/error 不显示通过，取消后不留占位。
4. **前端安全状态准确**：inflight 按 session/请求代次区分，旧请求不能回滚新会话；unknown 不假装 safe；standard 的真实工作区外访问语义在界面明确呈现。

验收：模型改名/单项能力更改不丢其他覆盖；压缩后的关键约束进入实际 adapter 请求；并发池占满时诊断仍能完成/取消；快速 A→B 会话切换只显示 B 的服务端模式。

metadata/outputPreview 与消息投影一起放进 D3，避免多个人反复改同一条聊天链。原无选项 ask_user 失败测试依据选定产品语义修正，不能为了绿色改变可用的自由输入行为。

### D2 — 撤回必须可预测

引擎：保留逐操作证据，增加稳定操作顺序与文件前后版本/hash；提供服务端批量回退，按 workspace/path 排序和互斥处理；目标集合由 session/turn/明确 ID 确定，不从 UI 当前200条列表推导“全部”。回退前检查当前文件；冲突返回可审查结果。

前端：一次提交回退意图，显示影响文件、冲突、不可回退项和部分完成；不对同文件历史快照发并发 POST。“仅保留”与“Git暂存”保持各自含义。

验收：A→B→C 回到准确目标；后续人工修改保留并报告冲突；超过200条范围完整；同时间戳仍有稳定顺序；重复请求不会重复破坏文件。第一版允许明确报告部分完成，不要求跨整个工作区文件系统事务。

不做完整 checkpoint，也不承诺撤销 shell/MCP/网络的所有外部副作用。将 hash/锁/冲突结果供 D6 复用。

主要位置：E `src/storage/changes/index.ts`、`src/api/http/routes/changes.ts`；F `ChangesPanel.tsx`、`FileChangeCard.tsx`、消息回退入口。

### D3 — 一次改通根运行、审批与工具结算

增加轻量根运行记录：run/session/turn/message 身份、状态、pending、outcome、原模型/工作区。正文继续使用现有历史；子代理继续用现有 v1，不另造第二套完整 RunStore。

同批完成：

- E 产生稳定 ID，F 回填，不再用“第一条相同正文”定位删除/截断/重试；session 写入/删除/压缩在当前单进程内序列化。
- 统一根/工具的 succeeded、failed、cancelled、interrupted、waiting；HTTP metadata、tool outputPreview/耗时完整透传；传输 done 不当业务成功。
- pending 持久化，回答按 request ID 幂等；刷新/重启仍可回答；旧审批工具卡有明确最终状态。
- 批次先判断批准需求再产生对应副作用；所有已启动调用都完成结算，某一项等待/失败不能漏掉兄弟结果。
- 第一版保守调度：可证明只读的工具允许并行；同文件写入互斥，未知副作用工具串行。子代理可保持独立状态/并发，但写入仍遵守文件级约束。
- safe 中批准与实际执行判定一致，移除批准后又走不相容旧白名单的双重语义。skill/MCP/网络等可达路径复用控制入口，不能借工具名称绕过模式限制；暂时无法可靠控制的扩展在受限模式明确不可执行。
- 已绑定知识在检索层过滤；code 模式未请求的知识不要无条件引入，避免把 RAG 范围问题留在主聊天里。

验收：连续两条“继续”只操作指定轮次；待审批时重启可恢复；重复回答只受理一次；批准前无对应副作用、拒绝不执行、批准后执行；混合工具批次每个已执行调用都有终态；引擎重启将运行中记录标 interrupted，不自动重跑未知副作用。

不做跨进程租约、分布式执行恢复、逐 token 事件落盘、自动续跑模型请求或团队邮箱。已有状态/存储能承载就复用。

本卡执行策略整改限定当前 F code 可达路径；先修已知内置工具和扩展的接入边界，不以重写 general 平台全部执行器为完成条件。D2 可先按现有 session/明确 change ID 实现，turn级回退在本卡统一ID后接入，避免两张卡互相阻塞。

主要位置：E `react.ts`、`chat.ts`、会话/状态存储和工具策略；F `host.ts`、`shared/ipc.ts`、`useChat.ts`、`chat-history.ts`、`pending.ts`。

### D4 — 用当前轮快照修复恢复

E 返回当前轮投影与同一水位 eventId；复用内存 StreamBus，并在快照获取/后续订阅之间提供有界回放。F 用快照替换该轮，再应用水位之后事件；main 保留 ID，renderer 去重。不拿 status 的服务器最新游标代替已消费游标。

已结束/等待的运行也可查询。todo、附件引用、已有changes从持久记录补回历史。重启后依靠 D3 记录显示真实 outcome；不承诺重启后自动继续模型调用。

验收：thinking/toolArgs/结果/pending/结束边界断线或刷新，不缺帧、不重复、不重复启动工具；会话静止时重开仍有todo与文件变更；停止既中断流又取消服务端运行。

### D5 — 模型请求更快、更稳

在 D3/D4 身份和恢复约定稳定后，正文按真实 delta 输出，去掉等待全文后20字模拟输出。工具前说明作为当前迭代内容表达，不因后续产生 tool call 而重复正文；最终历史与可见内容一致。

stream fallback 只在本次请求尚未向消费者交付进度时切换；已有正文/工具进度后失败保留部分结果并给出准确错误，不能重放整轮副作用。显示实际使用模型与用量。

复用已有请求预算估算，修 context-window 判定与压缩失败兜底，纳入 system/tools/输出预留；不重新实现整个 tokenizer/预算体系。

验收：可控provider延迟结束时，首段正文已在UI显示；流前失败可切备用、流后失败不重复文本/工具；超长上下文可控压缩或明确拒绝，关键约束不丢，费用统计不重复。

### D6 — 增加精确 edit，复用现有文件变更界面

先做一种明确的文本编辑协议：目标文件、预期内容/hash、唯一匹配的 oldText/newText；匹配不唯一或版本过期就失败并返回可解释原因，不猜位置。新工具加入 code profile 和 canonical tool metadata。

复用 D2 的文件锁/版本检查与 ChangeStore，F 用已有工具卡、diff、keep/revert/跳转接入。无需新建编辑器，也不先支持所有 patch 方言、Notebook/Office 格式。

验收：普通单处/多处明确替换、CRLF、Unicode、文件变化、重复匹配与不存在匹配；修改前置条件失败时文件不变；改动可审查和回退；实际模型请求能看到工具schema。

## 4. 后续按需求取下一张

**D7 后台命令**：独立 Agent job ID、输出读取、退出状态、进程树取消；F工具卡可查看和停止。复用现有 execute_cmd 能力，但不直接借用用户人工PTY的权限。先做同进程后台任务；不承诺系统重启后重连或自动重跑命令。

**D8 LSP消费**：先补请求超时/取消/退出清理，统一 markers 与 Problems 数据源，再补 rename/signature/symbol/补全 additionalTextEdits；未替换的功能保留可用 fallback。Agent 可调用的语义工具另行验收，不把 UI provider 当模型工具。

**D9 Windows分发**：E制品复制进F extraResources，native依赖/skills/assets齐全；在无同级仓库和开发依赖的环境从resources启动。用当前配对协议、本地模拟provider跑聊天→工具→审批→取消/恢复→重启。无需先做自动更新、跨版本回滚或所有平台。

暂不排入第一阶段：完整MCP协议/OAuth/资源管理、Hooks/插件市场、Agent mailbox/worktree隔离、Flow/Cron/通用任务队列、长期记忆产品化、通用RBAC/远程文件同步、云服务/语音、独立SDK发版。已有可用能力继续保留；这些方向在真实需求出现时单独估价。常用本地MCP明确成为阻塞时，可把标准stdio支持提前为下一张卡。

## 5. 人员与并行安排

按模块设稳定负责人即可，不要求额外人力，也不是现在创建新聊天/执行任务：

- 宿主/联调负责人：D0、构建标识、认证拦截、测试入口，后续 D9。
- 文件与配置负责人：D1模型配置、D2，然后 D6；与运行时主线可并行。
- 运行时与聊天负责人：D3 → D4 → D5，统一负责 producer 和 reducer 的协议修改。不要同时让多人各改 `react.ts/useChat.ts`。
- 余量用于 D1 的 adapter摘要/诊断/安全状态等独立小修；Electron E2E 始终单 worker。

实际排队：

```text
先并行：D0 + D1
再并行：D2（文件） + D3（运行/聊天）
随后：  D3 → D4 → D5
同时：  D2 + D3的工具契约稳定 → D6
收口：  当前两仓配对验收；达到D0–D6目标即结束第一阶段
下一张：长命令卡住选D7；语言服务影响大选D8；准备分发选D9
```

允许 D3 拆出小提交先合并，但不要单独启用只改了 producer 而 consumer 尚未支持的新协议。当前引擎内置控制台/SDK若仍属于本轮使用范围，完成最小当前版本适配或明确界面不可用；不承担不存在的历史发布兼容。

## 6. 每张卡的完成标准

1. 两仓任务同时写明 producer、consumer、错误/取消/历史行为；E内部实现修复也应确认真实 F 行为。
2. 针对已知失败场景做有副作用断言的测试；不为每个小函数堆镜像单测。沿用现有本地模拟provider和隔离目录。
3. 显式构建 E 与 F；F 的 pretest 只构建 F，不能拿旧 E dist 验收。
4. 涉及通信/IPC/交互的改动跑真实 Electron，按 F/AGENTS 单 worker；现有3项子代理生命周期测试继续作为回归。
5. 保存实际 entry/build/protocol；当前配对成功，错配给明确错误。发布历史四组合留到真正有已发布版本后再引入。
6. 第一阶段验收任务是“真实 IDE 完成一个多文件修复，能审查/精确编辑/测试/取消/回答审批/刷新恢复/准确撤回”，与可控故障用例一起判断完成；不使用工具数量或Claude功能数量作为完成指标。

优先级依据是当前用户路径的收益、已复现问题、改动范围与后续复用。没有现成的工时测量，不给未经拆解的几天追平承诺；D3是主要不确定项，实施前先把记录与事件schema定下来，其余任务遵循该小契约推进。
