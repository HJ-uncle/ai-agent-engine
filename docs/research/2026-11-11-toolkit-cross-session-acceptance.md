## 发现与修复

1. **技能管理 ID 与执行 ID 混用。** 管理回执原先只给路径 hash，AI 可能将其写入 Agent 的 `skills`，造成新会话没有对应技能。现在回执同时提供 `executionId`，工具参数明确用途；误传无法解析的管理 hash 会明确报错。合法的同形执行 ID 仍可绑定。真实注册器测试还检查了停用及换工作区的边界。
2. **AI 提交重复技能头部。** 模型有时向 `skill_create.content` 提交完整 `SKILL.md`，而工具会再生成头部。现在参数明确只需正文；与输入完全相同且没有额外字段的冗余头部安全去重，冲突或额外元数据明确拒绝。完整文档编辑仍使用 `skill_update`。
3. **验收断言加强。** 工具覆盖只计当前运行中 `metadata.success === true` 的回执，按消息 ID 去重。技能结果按 JSON 精确比较 `receipt` 和数值，MCP 解析实际工具结果，避免宽泛数字匹配误中 UUID。

修复执行 ID 后的 59 项技能/Agent/跨会话定向测试通过；头部规范化后的 39 项技能/跨会话测试通过（包含前述重叠用例，不累加为 98 项）。类型检查及构建通过。前端本轮未修改。

最终构建又执行一轮真实 AI 技能回归：A 创建只有一份头部的技能，AI 自行按 `executionId` 创建绑定 Agent；重启引擎后 B 实际 `get_skill`，JSON 严格等于原随机回执与 `total: 33`。两项检查通过。最终引擎构建为 `sha256:23f3b9115537677c9721fc6518dfd05500330de80db12efbe394310a780cd4c5`。
