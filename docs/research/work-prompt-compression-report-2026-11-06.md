## 最终实现

- `list()` 保留完整目录和原始本地化说明；`listForModel()` 提供等义紧凑说明；`listForRequest()` 选择本次真正发送的定义。
- 默认短请求携带 13 个常用工具和 `load_tools`。加载工具的目录仍列出全部当前获授权能力；需要时先加载，下一模型请求获得该工具完整参数 schema 和说明。完整目录为原 63 项加 1 个内部加载工具。
- 工具的必填项、类型、枚举、数值限制、输出结构、执行模式及权限检查没有删除。独立对照审计验证原 63/63 工具的非描述 schema 与基线一致。
- 父代理、子代理和兄弟代理各自持有加载状态。加载依据当前 `ctx.tools` 的授权范围；调研代理不能通过加载恢复写入、命令或递归子代理权限。
- 加载器以实现身份识别，不能由同名 MCP 冒充。外部/MCP 定义不压写、始终完整呈现；新增大量 MCP 时不承诺仍小于 10K。
- 重启依据配对成功的结构化调用/回执恢复可见工具，不从用户正文恢复。注销或同名重注册清理旧状态；同批“加载并猜参数调用”不会直接执行未呈现的工具。
- 系统规则去重，发送与统计共用构建来源；保留主动委派、完成实例续用、只读边界、交付和验收规则，即使对应工具暂未加载。中文用户答复规则保留。
- 用量分项按每次实际发送的定义计算，不用初始目录比例摊分。分项仍是本地估算按供应商总输入分摊；总输入来自真实回执。

主要代码：[`model-tool-loading.ts`](../../src/tools/model-tool-loading.ts)、[`model-tool-definitions.ts`](../../src/tools/model-tool-definitions.ts)、[`execution-protocol.ts`](../../src/core/execution-protocol.ts)、[`react.ts`](../../src/core/agent-loop/react.ts)。完整约束见[系统迁移表](system-prompt-compression-migration-2026-11-06.md)及[工具契约清单](../../src/tools/model-tool-definitions.contracts.md)。

## 未解决问题与结论边界

**文本精确复制仍未通过。** 基线经常漏做原地编辑且复制丢尾换行；v2 已正确原地编辑，但目标副本仍可能丢尾 LF，部分样本尝试计算哈希的命令进入标准模式待确认。没有自动批准。不能因为 token 下降就把这种回答判为成功。

**记忆彻底删除仍未通过。** forget 对原 ID 生效，但另一自动形成的独立记忆副本还含同一测试偏好。基线与 v2 均复现。这是“用户要求的内容清理未完成”，不是简单的 forget API 失败。

**极长输入有既有 SQL 边界。** 1200 行资料在基线与 v2 都会在根任务创建前触发 SQLite expression depth 1000 错误；600 行、实际主请求 16,878 tokens 可以成功。详见[极限报告](work-prompt-compression-limits-2026-11-06.md)。

浏览器本轮只真实验证能力发现和未连接反馈，没有连接用户的 Electron 页面、真实点击外部站点或发送消息。Office 真实模型测试以 XLSX 为主；其他原格式由工具回归与 schema 对照覆盖，不能声称逐一完成了所有格式的视觉验收。模型样本只来自上述一个配置，有限样本不能证明其他模型、任意复杂任务或所有功能绝对等价。
