## 结论与边界

已加强默认策略：已知、无依赖的小文件读取与不同目标写入，在同一次模型响应提交多个原生工具调用；修改、纠错和必要复查同样支持批次。大文件按输出预算连续分页，目录可按需返回实际字节大小。不增加批量工具数量。

真实 Work 会话已验证 **6 个不同输入同轮读取、6 个不同目标同轮写入、Word/Excel/PPT 三个不同目标同轮创建**。验收配对成功回执、检查最终文件，不能把重复路径或失败调用计为成功批次。读取调用可由现有执行池并发派发；写入仍按序落盘、整批结束再请求模型，保留版本、权限、取消、交付屏障。不是文件系统级整批原子事务，也不承诺磁盘同时写入。

**尚不能保证模型每次都一次写对或把所有纠错合并。** 文本用例初次写入多次漏尾 LF；最终通过的一次仍有串行纠错，主流程携带工具定义的请求共 13 次。此次完成了批次策略、分页与显示兼容修复，不宣称所有任务都能用“两次模型请求”完成或行为已达到 100% 稳定。

## 实现

| 层面 | 改动 | 保留的约束 |
|---|---|---|
| 执行协议与工具说明 | 明确同响应多调用，独立写入/修改/检查批量提交；写前核对格式、空白及版本 | 依赖上一项回执的参数、同文件或共享资源操作不能盲目并发 |
| 目录 | `list_files(includeSizes:true)` 返回普通文件实际字节大小 | 默认格式兼容；不跟随符号链接；保留遍历数量、大小、时间预算 |
| Work 普通 UTF-8 文本 | `auto/full` 返回预算内完整 JSON 连续页；小文件不再固定截在 300 行 | `Code/exact/JSON/CSV/Office/image` 保留各自路径；本轮未统一所有格式的分页 |
| 超长行 | `start_column` 与 `nextStartLine/nextStartColumn` 续读 | 1 起 UTF-16 列，边界不拆 surrogate pair；只在 Work 普通文本 auto 接受列参数 |
| 回执 | 大小、整文件版本、页范围、是否完整及续页位置 | 跨页版本变化须重新读取；`numberedContent` 是展示，不替代精确复制的 `exact.content` |
| Office 参数 | 明确 title/author 只适用 DOCX/PDF/PPTX create，Excel 省略 | 不放宽底层格式校验；防止同批 Excel 因无效参数失败 |
| Aether 前端 | 新回执显示正文、行范围及“还有更多内容”；兼容旧 exact/content、文本包络及两种 hash 格式 | 不再将正文折入版本元数据表；保留现有工具行、折叠与样式 |

## 尾换行问题的证据边界

前 3 版的 18 条首写 `_rawArgs` 本身均没有 LF。实际路由是 Anthropic 协议，不经过 OpenAI XML 的 `trim()`；原始流参数逐字保留，真实 AnthropicAdapter 的纯内存 SSE 回放也能保留 LF。可排除本地该解析路径裁掉换行，但现有记录无法区分模型漏写与上游网关变换。新增首次写入空白说明没有消除这个问题；不把它写成已彻底修复。

工具仍按用户给定数据精确写入，不擅自给所有文件补换行。不同文件的纠错可批量，但真实模型并非每次都充分采用。复算说明：`.e2e-tmp/read-batch-20261109/newline-provenance.md`。
