## 验收方法

- 不改变原题：原地修改源文件、另存副本、报告真实 SHA-256；保存记忆后按用户要求删除并验证。文件按磁盘字节验收，不按模型“已完成”的表述验收。
- 每个候选冻结源码，保存源码 SHA-256 清单、模型请求用量、会话 JSONL、数据库与文件后置条件。失败和启动失败保留，不覆盖原记录。
- 最终版只检查每轮最后的非工具调用答复，防止中间文本掩盖错误最终答复；记忆数据库断言前等待当前范围活动提取数归零及模型请求稳定，超时算失败。
- 供应商用量按字段合并流式快照，后值覆盖前值，不累加快照。输入包含缓存读写；辅助标题、记忆提取和子代理调用计入整项开销，缺失用量不算零消费。
- 测试会话、模型配置副本、工作区、记忆、计划及定时任务完全隔离；生产数据库只读取模型配置，密钥不进报告。未自动批准被权限策略拦截的命令，未重启当前 Aether。

## 为什么增加提示词

文件工具底层已经能逐字节保留 UTF-8、BOM、CRLF 和尾空格。真实轨迹显示模型自己在 `write_file.data` 中删去尾换行、把 CRLF 双重转义；有时面对不同的两个哈希仍声称相同。Anthropic 流解析、JSON 修复与参数规范化的合成输入检查保留了全部字节，不能把错误归咎于工具自动 trim。

只在工具说明中增加“保留换行、核对哈希”不够。最终增加中文的顺序和纠错示例：先原地编辑源，再读取修改后的完整内容，另存并比较双方哈希；若副本有误，用 `edit_file` 的唯一原文替换纠正，实际改变参数后重验。明确 JSON 只转义一层、末尾换行/空格也是内容，源无换行时不能擅自添加。工具返回的整文件 SHA-256 可以直接报告，无需再跑命令。

| 文件候选 | 原题通过率 | CRLF+BOM | 无尾换行+尾空格 | 判断 |
|---|---:|---:|---:|---|
| 上轮 v2，本轮重新测 | 0/3 | 未重测 | 未重测 | 原失败仍存在 |
| v3：工具说明与可见回执补强 | 0/3 | 0/1 | 0/1 | 仅重复原则仍不足 |
| v4b：增加中文操作顺序和转义说明 | 1/3 | 0/3 | 1/3 | 有提升但不稳定 |
| v5：明确使用精确编辑纠错并给例子 | 3/3 | 3/3 | 3/3 | 9/9，独立复读磁盘及最后答复确认 |

新增回执仅在 UTF-8 exact 模式显示 `byteLength`、`trailingLineEnding`、`contentIsComplete` 与明确的 `sha256`；图片/普通读取契约保持兼容。没有添加针对某一验收题的文件内容、哈希或硬编码答案。

## 记忆修复

旧版本轮复测仍为 0/3。失败既有模型指令不足，也有产品缺陷：自动提取把显式保存的信息改写成第二份记忆；检索隐藏独立副本且不展示其 ID；模型只删除原 ID 后又请求确认。

修复包括：

1. 检索返回每个真实 ID、范围和原文，独立副本不再被隐藏。内容删除请求包含已确认的同内容副本；ID-only 删除仍只作用于那个 ID，不扩大范围。
2. `recall` 和 `list_memories` 增加可选的字面关键词和分页，返回 `hasMore/nextOffset`。关键词区分大小写，不解释正则或 SQL 通配符。删除一批后必须从 offset=0 重查，防止跳过移动到前页的副本。
3. 自动提取读取配对成功的结构化 remember/forget 回执，禁止重复保存或复活其事实。严格相同字符串由代码排除；同轮无关新事实仍保留，用户之后明确要求重新保存也可以成功。
4. 在执行轮开始前预约提取任务；同范围删除与最终自动写入共用短临界区。若模型或 embedding 等待期间发生删除，旧提取结果作废，携最新排除信息重新提取。连续三次变更则明确返回提取错误，原会话记录保留。
5. legacy 编辑/重生成只提取当前轮，避免扫描完整旧历史重新保存已删除事实。

这不是对任意同义改写的确定性语义证明：同义识别仍依赖提取模型。运行期协调覆盖单引擎进程，其他进程直接修改同一数据库不受此锁保护。没有新增永久的明文删除日志；工具回执和会话历史仍按既有策略存储，删除记忆不等于删除聊天记录。

## 长输入与极限

查到两条独立 SQL 路径：记忆关键词检索、知识库自动 RAG 回退，都曾将长输入展开成大量 LIKE/OR 表达式。只修第一条仍失败；两条都改为参数化词表查询后，1200 行、2000 行真实 Work 测试通过，保留全部关键词及原有租户/作用域限制，没有截断用户正文。

中间验证的完整主请求输入分别为 28,403 和 43,599 tokens，正确返回首尾标记。最终整合版还重测长输入、完整工具加载和不可信文档中的伪造删除指令。10K 目标针对默认短请求，不限制用户正文、长历史或实际加载全部能力后的上下文。
