# 子代理协作与总 token 优化：实施和验证

日期：2026-11-09。目标是降低父代理及所有子代理的合计消耗，保留有效上下文、权限、产物质量与正确收尾。不是把主会话的消耗转移到不显示的子会话。

最终版本实测：普通三格式办公 **282,778 tokens**；用户指定两名执行者时，父子合计 **593,862 tokens**，两个 child 均成功且主代理统一验收交付；问候 **7,986 tokens**。定向回归 **63 文件 / 1,131 项全部通过**，引擎类型检查、构建通过。内容结构和流程通过不代表每句文案均无误，独立事实抽查见后文。

## 已落实的机制

| 环节 | 修改 | 节省来源及边界 |
|---|---|---|
| 多个已选协作者 | 没有明确任务时先提交一次完整分工，校验通过后才分别启动；不广播整套需求及主历史 | 每个 child 只拿自己的任务；任务文本优先引用资料，不复制草稿、系统规则和教程 |
| 分工回执 | 返回选择标识和简述，不再原样返回全部 task | 避免刚写过的任务再次进入工具结果；原始调用及 child 任务仍可审计 |
| 模型跳过分工 | 一次纠正后仍不分工则明确失败 | 避免无效循环，也不伪造已使用用户选中的代理 |
| 旧代理复用 | directory / followup / resume 使用真实持久工作区绑定，兼容请求省略路径 | 修复旧 child 被误拒而反复新建；权限收缩、目录越界、绑定变化仍拒绝 |
| 协作工具加载 | 目录/启动/续用成功后，把已授权协作工具加入下一轮定义 | 减少额外 load_tools 往返；不新增权限 |
| 主代理收尾 | 引擎等候真实执行器，结果进入主模型后才允许最终收尾 | 不靠模型轮询等结果；收到结果不等于验收，压缩索引不能冒充结果正文 |
| 历史并发变化 | 认证通过后，若发送前历史变化则重新读取并预算，最多刷新 8 次 | 两道发送前检查均覆盖；没有发请求不记模型轮次/attempt/usage；已开始发送、取消和权限损坏不会盲重试 |
| 大段成功写入 | 旧 write_file 正文及 Office Markdown 在模型输入中改用可恢复索引，保留最近两批 | 仅处理严格配对、同任务且成功的内置调用；原始持久历史、界面和审计不改 |
| 参数恢复 | search_history 支持 messageId + toolArguments + contentOffset，返回原参数 JSON、hash 和分页 | 不再出现“有索引但找不回参数”；恢复工具不可用时还原参数全文 |
| 办公子代理 | 主代理、继承型/配置型/恢复后的子代理共用 Office 流程和准确技能目录 | 复用共享草稿，仅补必要缺口，复用同版本校验；Excel 修改后重算；只读 research 仍无写权限 |
| 办公批处理与报错 | 小型多表可以一次 create；PPT 校验报告具体页/行/列、数量及限制；成果上报字段明确 | 不再把短表强拆成逐张追加；参数错误可定点修正，原版式限制、版本与原子发布合同不变 |
| 路径交接 | 运行环境明确 relativePathRoot，跨目录共享文件使用真实绝对路径 | 输出目录可与项目目录不同；任务文本不能改 cwd，不靠找同名文件猜路径 |
| research 的代码图 | 授权检查先于索引操作，只读查询使用独立稳定快照 | 避免查询意外改源索引/.gitignore；源 DB/WAL 不稳定或过大时明确降级 |
| 前端 | 子代理面板手动刷新传 force，保留原有图标布局 | 防止点刷新仍只读旧缓存；协作派发协议继续兼容现有前端 |

默认策略按任务规模选择：独立交付、较长调研优先委派；短回答、小修改、一个小批次能完成的任务直接做。用户明确选了协作者则真正分工执行。**代理更多不代表总 tokens 更少。**

## 验证口径

- 走真实 Work HTTP 路由与实际注册工具；模型来自现有配置，生产配置/数据库只读。测试用隔离目录和隔离数据库，未重启用户正在使用的 Aether。
- 模型为 `deepseek-v4.1-flash-1017`，实际 Anthropic-compatible 协议。输入包括缓存输入，输出计一次；流式 usage 用最终字段覆盖早期快照，不累加快照。
- 每轮抓取真实 fetch 回执，包含父、子及后台模型调用。另按 session/message ID 去重独立复算持久 usage，两者核对。数值是 tokens，不是金额。
- 失败试验单独列出，不剔除、不计为成功。v3–v6 团队测试上限为 45 次实际请求、300 秒、累计输入保护 600K；保护包含在途请求的保守预留。v7 用相同产品版本，将评估保护调为 55 次/300 秒/900K，以验证完整交付；没有提高生产预算。保守预留会在真实用量尚低于阈值时提前阻止请求。
- 成功要求：三种真实成品、草稿先于生成且不交付、内容及结构最低要求、文件 hash、公式缓存/错误值、最终交付后停止修改、计划闭合、子代理终态、后台静止。文件检查只读取，不修改已交付产物。
- 未做原生 Office 视觉渲染；结构正确不能宣称版式视觉全部通过。公式复算使用引擎计算器，不是独立 Excel 实现。

v1 办公产物包括 Word 45 段、Excel 3 表 120 个非空格与 1 个公式、PPT 8 页。独立复核了主要事实：项目模块、启动方式、主题、悔棋、落子、存储及无 ServiceWorker；测试数字 18 + 47 = 65 正确标注为既有说明、本次未重跑。不是只靠文件存在判通过。

v7 普通任务为 Word 55 段、Excel 4 表 209 非空格和 4 个缓存公式、PPT 8 页；团队任务为 Word 38 段、Excel 3 表 117 非空格和 3 个缓存公式、PPT 9 页。团队主代理 **322,310**，两个 child 分别 **139,944 / 131,608**，合计与提供方回执完全一致。完成后没有继续写成品，计划闭合，后台静止，最终正文不重复列下载链接。

v7 团队实际输入 581,846，但它是在 **900K 保守保护**下完成，不能据此把之前的“600K 保护测试失败”改写为通过。全部真实试验含失败共 213 次网络请求，已记录总消耗 **至少 3,698,985 tokens**；v6 有一个中断响应缺完整回执，精确总量未知。这是开发验证的累计开销，不是单个用户任务成本。

独立内容抽查发现 v7 普通 PPT 两处措辞问题：第 2 页“可离线安装”扩大了 README 的“离线运行/manifest 可添加桌面”，与第 8 页无 ServiceWorker、首次需联网的限制不一致；第 7 页“自带无头 Chrome”不准确，测试脚本实际寻找系统 Chrome/CHROME_PATH。这些测试产物未手工修饰以伪造通过，因此不声称文案事实零缺陷；平台流程、公式和文件合同通过，与内容语义质量应分别评价。

团队 DOCX 还有一处措辞问题：“运行测试前需先启动本地服务器”将端到端测试的前提泛化到所有测试，规则单测并不需要服务器。独立复核同时确认：普通 Excel 缓存 15/6/3/10，团队 Excel 缓存 15 个文件/99,484 字节/65 项既有测试，均按实际行与文件大小重新计算吻合；三个 child 成果的报告 hash、交付 hash、当前文件 hash 全部一致。团队 PPT 的一次重复 create 是首次超宽校验失败且未落盘后修正，不是已交付成品被反复编辑。

v3 暴露了缺失子代理 Office 流程、重复调研、工具参数错误及不必要编辑，随后已修。v4 子代理已能读取 Office 指南，却又暴露共享草稿路径交接错误，额外产生多次找文件请求，随后修正。

v3/v4 的终态错误为历史预算后变化；v4 深入复现表明：测试 fetch 的累计额度保护先抛异常，被 SDK 当连接失败重试，重试期间 child 完成改变历史，第二道检查正确拦截。真实 Anthropic SDK 离线测试已复现此链路；未发送请求的正常重预算也通过验证。评估器现将本地额度拦截记录为 `guardFailures` 并返回不可重试的本地 400，不再假装网络失败。旧轮次没有该字段，不能补造未记录的触发时刻。

## 与历史事件比较

历史 2048 办公事件共 **1,470,998** tokens；v7 普通三格式办公为 **282,778**，参考降幅 **80.78%**；指定两名执行者为 **593,862**，参考降幅 **59.63%**。这是同模型、同项目的历史参考比较；上下文、需求表述及运行配置未全部严格控制，不能称为严格 A/B、不能保证未来任务都有同样降幅。普通任务的改善不能归功于子代理，因为该次没有委派。

同一轮 v7 的团队成本约为普通执行的 **2.10 倍**。因此保留小任务直接做、复杂独立任务再委派的默认策略；明确选择的协作者仍实际执行。不能宣传“多开子代理必然省 token”。

用户后续指出“同时出现三条读取，但 token 增长三次”，复核发现批量仍不稳定：v7 普通任务三次 Office 检查分别占用第 7/8/9 个模型响应，团队主代理为第 13/14/15 个响应。此前“流程通过”没有要求这三次检查合批，不能当作全阶段批量优化完成。生产会话也有三个源码分轮读取的实证；详见 [批次与计费复核](./batch-request-accounting-audit-2026-11-09.md)。

仅“完成写入参数投影”的离线回放，估算 web-go 净减少 **72,117**、2048 净减少 **121,425** tokens，已扣除恢复工具定义开销，交付后不使用索引的请求按 0 收益计算。这是本地组件估算，不是 provider 实测，不能与真实用量直接相加。

## 回归与交付边界

实现覆盖 JSONL/SQLite、工作区续用、分工验证、真实子代理完成/恢复、主代理验收、参数恢复、压缩、运行中消息与历史变更。最终按文件采用最新结果去重：**63 文件、1,131 项通过，0 失败/跳过**，详见 [测试统计](./team-token-optimization-tests-2026-11-09.json)。此前过期断言、真实执行器夹具和超时修复前的失败日志仍保留，没有将同一测试多次运行累加为更多覆盖。

`npm run typecheck`、`npm run build`、`git diff --check` 均通过；前端协作合同 7 项及前端类型/构建通过。v7 的源码 manifest 与最终源码逐文件 hash 一致，无测试期间源码变化。引擎构建标识为 `sha256:ee435239fe01adb3ae6951a2c5d7c4189eec567af87f9cbe95a88d357ba63693`。

为补齐必要协作和办公规则，显式加载全部相关能力后的局部 system 文本估算约 5,046 tokens，测试上限由旧 4,500 更新为固定 5,200。该局部估算不含全部真实请求，不等于首轮总输入；最终问候真实输入为 7,974，仍低于 10K。没有通过删验收/权限规则凑小数字。

只读代码图快照上限为 64 MiB；源 DB/WAL 必须稳定且无非空 rollback journal。不满足时明确返回 `CODEGRAPH_READONLY_UNAVAILABLE`，使用 grep/read_file；不会悄悄对源库做迁移。SQLite SDK 本身忽略 readOnly 选项，因此没有把该选项当作只读保证。

本轮未改生产模型、未删用户历史、未提交 Git。当前运行的 Aether 未重启；源码和构建通过不等于运行中的旧进程已加载新版本。
