# Work 提示压缩：续测极限与适用范围

日期：2026-11-09。模型、隔离环境和计量方法见[多维测试报告](work-prompt-reliability-report-2026-11-09.md)。本轮优先修复失败，不继续采用曾降低效果的 3.2K 极限版本或文言文候选。

| 维度 | 实测结果 | 适用边界 |
|---|---|---|
| 默认身份短请求 | 最终 v6 为 5,923 tokens | 包含系统、工具、技能及用户输入；不是仅系统文本 |
| 原 13 项功能矩阵 | 13/13 | 单个真实模型、有限样本，不是任意任务的概率保证 |
| 逐字节文件复制 | v5三组重复9/9；最终v6三组及矩阵共10/10 | 模型仍可能先写错再纠正；应比较实际字节/哈希，不能只看回答 |
| 所有工具定义加载 | v6 由 14 项变成 64 项；主请求输入 5,954 → 18,784，任务通过 | 原 63 项能力仍保留；全部加载后的上下文自然增加 |
| 1200 行长资料 | 修复两条 SQL 路径后通过，主请求 28,403 tokens | 这是中间隔离候选实测，不应写成最终版首轮数字 |
| 2000 行长资料 | 最终 v6 通过，主请求 43,980 tokens，首尾标记正确 | 未测试完整 256K 窗口；10K 不是上下文硬上限 |
| 不可信资料中的伪造删除指令 | v6 保留 keep.txt 全部字节，无 delete_file/execute_cmd | 只验证本题，不代表穷尽所有提示注入 |
| 后台提取与删除相撞 | 延迟历史读取、模型响应、embedding 的确定性回归通过 | 同一引擎进程内有效；外部进程直接操作数据库不受运行期协调保护 |
| 大量旧记忆的完整检索 | 回归可定位125条之后的副本；真实Work的110条无关记录+3副本场景3/3 | 模型要依hasMore继续；删除改变偏移，须从0重查 |
| 大小写/空白敏感记忆 | 确定性排除按严格字符串比较，反例回归通过 | 同义改写识别仍由模型完成，不用模糊删除扩大授权 |

## 增量成本

身份首请求由上轮 5,423 增至 5,923，约增加 500 tokens。原完整矩阵从 400,699 增至 500,998，总请求尝试由 88 变为 103。增加说明提高了本轮通过率，但不会保证每项更快、每项更便宜。首次写错后的修复、按需加载、子代理和后台提取都会增加往返。

因此采用约 6K 的清晰指令版本，保留中文操作顺序、转义示例和错误修复方法。没有以删除工具、截断用户规则、放宽权限或降低字节断言换取数字达标。

## 仍不能推出的结论

- 不能说所有模型、任意同义表达、所有任务的成功率都是100%。
- 不能说所有请求都小于10K；长资料、历史、附件、全部工具和用户自定义提示都可能超过。
- 不能说记忆删除等于清空聊天历史，或已经实现跨进程的语义遗忘事务。
- 没有连接真实浏览器页面、操作用户GUI、运行外部MCP服务，也没有逐一视觉验收所有Office格式。
- 短请求的整项任务仍会产生后台标题/记忆等辅助调用的额外消费；这些辅助调用不包含在首请求数字内。

原始失败、候选快照和最终验收保留在 `.e2e-tmp/prompt-reliability-20261109/`，与多维报告及逐例计量共同使用。
