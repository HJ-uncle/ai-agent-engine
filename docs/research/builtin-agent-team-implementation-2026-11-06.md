# 内置协作 Agent 实施记录

日期：2026-11-06。对应方案：[可行性调研](builtin-agent-team-feasibility-2026-11-06.md)。本记录描述实际落地行为；前一份调研中的“当前实现”是修改前快照。

## 已落地的行为

| 能力 | 本次实现 |
|---|---|
| 三类内置模板 | `research` 调研、`executor` 执行、`general` 通用；保存模板版本；同模板可有多个实例 |
| 调研权限 | 不提供命令、任意脚本、文件写入、成果发布或 MCP 初始化；代码图只允许查询已有索引；仍可保存内部计划、历史和协作消息 |
| 已完成实例继续工作 | 主 Agent 使用 `subagent_directory` 发现同父会话的实例，再用 `subagent_followup` 追加工作；终态实例复用 childSessionId、创建新的 runId |
| 运行中补充 | 活跃实例使用持久邮箱；同请求幂等，收尾已封口时明确拒绝，避免接收了却无后续执行 |
| 重启接续 | 持久目录和 continuation 可被新父执行发现；恢复历史和任务状态，不恢复已失效的执行权限，也不盲目重跑外部动作 |
| 同伴协作 | 当前根执行内父子、兄弟可发送消息，目录展示最新 invocation、状态、活动及输入是否关闭 |
| 显式选择后继续协调 | 用户选择的协作者以异步接纳方式启动，主模型不再先等待全部子任务完成；仍由原执行归属负责最终等待与取消 |
| 消息唤醒等待 | `subagent_wait` 可被父收件箱的新消息唤醒，返回 `pending/reason=message`；先订阅再查持久队列，取消/结束清理监听 |
| 子代理需要用户信息 | `subagent_request_input` 保留问题、选项及真实 child/run，当前轮进入 `blocked/needs_user`；主 Agent 转达并在获得答复后继续同一 child |
| 自动上下文压缩 | 沿用主子共享的 ReAct 压缩机制；本次新增子运行真实压缩状态持久化及前端提示，区分进行中、成功和失败 |
| 子成果交接 | `report_artifacts` 保存文件的不可变副本；父 Agent 用 child/run/artifact 三个身份显式采纳，保留提交来源 |
| 改动来源 | 文件改动保留 child/run；混合多个来源的合并 diff 不冒称由最后一个代理独自完成 |
| 工作区继承 | 依据真实执行归属继承父实际绑定，支持默认临时工作区；父目录或绑定版本变化后拒绝旧访问 |
| 前端 | 内置模板、多实例、继续/补充、待回答、明确回执与成果来源；主子会话共享 `WorkMessageContent`，普通对话展示正文、附件、过程与结果，取消详情页重复轮次卡和 tabs |

## 身份与持久化

模板是职责定义，childSessionId 是上下文身份，runId 是一次执行。已完成实例不常驻模型调用，不占并发槽；新一轮使用原子会话的历史和同一 ReAct/自动压缩机制。

新写入的子会话消息带有运行时生成的 `metadata.subagentRunId`，覆盖用户输入、助手回答、工具结果及输出续段。父 `rootRunId` / `turnId` 和已认证的历史来源保持原样。前端据此识别当前执行，旧记录不推测或回填所属轮次。

SQLite 保存运行索引、状态、邮箱回执、续用幂等接纳和成果 manifest。对话正文沿用配置的 JSONL/SQLite 历史后端；较大的工具正文沿用现有磁盘 payload 机制。成果字节保存到本地资产目录，manifest 保存引用。内存只保留活跃执行身份、监听器和有界显示状态，不承担重启恢复的唯一来源。

`subagent_directory` 每页最多 64 个实例，主提示只加入最多 8 个有界摘要，不把所有子会话全文复制进主上下文。选择新内置实例不读取旧子任务，续用只读取指定运行的头记录与冻结权限；自定义 Agent 只查询最新匹配项。复用可能减少重复调查，但不承诺所有场景都降低模型 token；旧历史相关性、长度和提供方缓存仍会影响成本。

用户已明确选择协作者时，引擎会提供基于真实执行归属的等待、取消和通信控制，即使主 Agent 的业务工具列表为空也能管理这些任务。这不添加文件、命令或 MCP 权限；未经明确选择的普通空工具配置保持不变。旧子代理的冻结工具权限也不会自动升级。

## 消息和提问的准确语义

- `queued`：已经持久接纳，尚未进入接收方上下文。
- `injected`：已经加入上下文，不表示模型已执行完成。
- `started`：新一轮执行已启动，不表示任务已完成。
- 输入封口：发送方收到明确的 closed；界面保留补充草稿，刷新状态后可继续原实例。
- 子问题：普通信息答复不构成权限批准。当前没有开放子代理直接代表用户审批。
- 如果主模型已封口或正在等待子任务收尾，子问题保留在 blocked 结果中，并标记 `deliveryUnavailable`；不会假称已经向用户提问。下一轮可据此继续原 child。

自动压缩在每次模型请求前检查估算输入、系统与工具开销及输出预留。默认阈值为有效窗口的约 92%（配置可调整），先轻量精简旧工具结果，仍超阈值才生成摘要。界面压缩提示取自真实 observer：开始、摘要提交成功或失败；没有发生摘要压缩时不伪造成功提示。摘要失败保留原历史，压缩不承担磁盘垃圾回收。

子代理详情默认展示连续对话，正文、附件和折叠过程与主会话共享组件；模型、轮次和统计收进信息按钮。完整历史使用有界分页，运行修订触发合并刷新，请求期间收到的新修订会在结束后补读。用户翻看旧消息时保留阅读位置，通过“查看最新消息”回到底部。真实 `partialOutput` 在落入历史前以临时消息显示，归档后去重，终态收起；它不会被伪装成已持久化历史。

已发布父消息上的子代理引用仍是不可变快照；打开详情后读取经过身份校验的独立子会话，可看到该 child 后续的消息。旧页首只剩工具结果时明确显示结果证据，不补造工具执行；失败和中断按真实记录显示。

重开任务只剩已发布引用时，详情通过现有有界发现和 summary 接口恢复独立的操作状态，核对租户、父会话、根会话及 child 身份后恢复续用入口。优先使用已知活跃/较新运行；引用本身不被宣称为最新运行。服务端最终校验同 child 的活动冲突与冻结权限。没有新增按 child 查询最新运行的 HTTP 协议，也不改写父发布快照。

续用接纳保留第一个真实父工具调用锚点，相同 key/正文并发重试复用同一次执行；改变正文会被拒绝。旧父执行身份、跨租户或跨父会话的续用也会被拒绝。

## 当前仍然存在的边界

- 并行开发仍需主 Agent 分配文件责任和单一集成者；没有新增每个子代理自动创建 Git worktree 或操作系统级写入沙箱。shell、MCP 不受内置文件锁完整覆盖。
- 主子共用执行内核，但权限并非无差别复制；子代理不递归创建子代理、不直接发布父最终成果、不直接审批。
- 旧根执行中的未消费消息不会无条件迁移到新根；保留原回执后由新的明确任务安排续用。
- 子成果暂时接收真实文件。内联图片须先保存为文件；视频等能力取决于实际工具和既有资产大小限制。
- 来源表示哪个 child 提交或观察了该版本，不等同于唯一作者证明。
- 自动压缩服务于模型有效上下文，不是磁盘清理。本次没有删除用户会话、进行 VACUUM 或运行资产垃圾回收。
- 压缩提示来自真实 observer 回执；重新打开能读取已保存状态，上一轮的压缩进行中状态不会沿用到新 run。中断后未确认的压缩不会显示成功。
- 完成和中断的上下文会被保留以供复用。共享资产字节的保留/垃圾回收需要独立引用检查，不能因某一次子运行删除就直接删除父成果仍引用的文件。

## 使用方式

在 Work 输入区选择内置调研、执行或通用模板；重复选择执行模板可以建立多个实例，任务正文写清各自职责。子代理详情中可查看多轮工作，已完成实例可继续，运行中实例可补充。也可以直接要求主 Agent “让之前负责组件 A 的代理继续修改”，由目录与 followup 选择相关实例。

这些是代码与构建产物的变更。既有运行窗口需要加载更新后的引擎与前端才会获得新行为，源码修改不代表该窗口已经自动更新。
