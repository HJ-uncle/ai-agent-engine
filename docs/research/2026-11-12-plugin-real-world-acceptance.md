# 真实插件创建、导入与客户端验收

这次验收使用 Windows 上的真实 Aether Electron 客户端和引擎。目标是五个由 Aether 内模型创建的插件、三个 GitHub 插件和两个独立编写后导入的插件。最终包是否可交付，以交付索引和对应固定 ZIP 的运行报告为准；中间草稿、成功的单项测试和模型的完成声明都不代表整体验收通过。

## 数据和作者边界

- 经用户授权，只读开发环境模型配置用于隔离模型调用；测试插件、会话、数据库、工作区与运行证据位于仓库 `.e2e-tmp/plugin-real-world-20261112/`。
- 五个模型场景的实现由 Aether 内模型通过真实管理工具生成；测试驱动提供业务要求、反例、宿主协议和实际失败信息，不替模型编写实现。恢复模型自产历史源码时记录其来源，继续使用原作者会话。
- 两个独立编写插件是图片交付工作台和工作区发布审计，不计入模型自主创建数量。
- 三个 GitHub 来源为 `remarkjs/remark-gfm`、`remarkjs/remark-toc`、`remarkjs/remark-frontmatter`。实际下载、导入和运行上游实现后，通过 Aether 适配工程包装业务页面并封装依赖；不宣称这些上游仓库原生支持 Aether 清单。包内保留固定提交和第三方许可证。
- 交付包只读取明确白名单中的源码 ZIP、脱敏报告字段和已审核截图，不包含模型配置、运行数据库、原始会话日志或凭据。

## 验收分层

1. 原模型创建、测试、发布经过实际审批恢复，工具审计保留每次调用及结果。自动压缩后的历史不能取代持久工具事件证据。
2. 独立业务断言覆盖非默认输入与业务边界；随包 `npm test` 验证独立 Node 协议，标准示例另外逐条经过宿主参数与结果校验。
3. 原生 ZIP 在新隔离存储预览、安装、发布、运行；不借用作者会话已安装的源码或依赖。
4. 真 Electron 页面输入、点击、文件上传和导出经过真实渲染层与主进程。保存对话框的目的路径由测试重定向，最终写盘仍执行产品代码，并核对字节、JSON、像素或哈希。
5. 检查浅色、深色、窄窗口、当前会话工作区上下文，以及关闭客户端后重启继续使用。界面成功提示不能替代磁盘副作用断言。
6. 两个迭代插件逐轮固定修订，验证本轮新增工具调用、功能增量以及前轮行为；不能用一次生成所有功能冒充三轮开发。

## 已修复的产品问题

### 大工程和协议读取被截断

普通模式的工具输出预算会截断完整工程 JSON，连宿主 bridge 字段也可能不可见。`plugin_get` 与 `plugin_get_template` 现在按实际输出预算返回目录或完整 JSON 分页，支持读取单文件、清单和单项协议。续页必须带同一修订；Unicode 边界、JSON 转义和批次调用的更小预算也纳入测试。没有提高全局输出上限。

### 局部编辑迫使模型重发完整工程

`plugin_update` 新增显式 `fileMode:"merge"`：未提交文件保留，删除路径单独声明。审批前合并为完整校验快照，审批后执行封存字节；版本冲突、更新时间变化和输入篡改均拒绝。默认完整替换保持既有语义，HTTP 接口不受影响。

### 沙箱页面缺少真正的保存入口

前端新增 `aetherPlugin.download`，通过原生保存对话框导出 UTF-8 或 Base64 文件。宿主限制单文件名和 16 MiB 解码上限，并在对话框完成后重新检查页面有效性。取消不写盘，页面销毁后也不写盘。不能用沙箱里的下载链接假装文件已经保存。

### 协议和报错不够精确

模板现在明确 `invoke` 的业务结果位于 `.result`、上下文为扁平结构、真实主题变量、工具输入与产物大小限制。HTML 校验分别报告缺文件、空页面、错误扩展名与实际字节超限，避免把文件缺失误解成 20 KB 页面超过 512 KiB。

### 多轮审批累计放大运行状态

真实模型续改时发现，公共运行帧重复携带所有已答复审批的完整工程、参数和确认文本。两段失败快照分别达到 1,188,697 和 1,341,752 字节，超过流队列的 1 MiB 限额。修复后公共 permission 投影不再发送私有 `pendingAction`，巨型展示参数与文本提供明确摘要，所有交互标识、状态与回答保留；普通问题保持原样。原快照对应公共帧降至 16,331 和 14,257 字节，不修改私有封存或提高队列上限。

管理工具的写入回执也改为修订、哈希和准确调用元数据，不重复返回源码；审批预览使用真实新增/修改/删除统计及内容校验值。前端显示文件变更清单，内容校验另行展开。新增测试实际完成八次增量审批，每轮关闭并重开 SQLite、恢复封存、发布 SSE，最后执行插件核对结果及未改文件。

## 模型迭代中的失败与恢复

Flow 的后续草稿曾在一次全量更新中误把已有实现替换成占位符。恢复材料来自同一模型此前生成的 r7 归档源码，由原作者会话继续修改；没有把人工重写实现计入模型创作。最终 r26 ZIP 重新经过独立业务测试、同参重复调用、真实客户端和导出验收，交付摘要记录恢复来源。

Project 的第一轮功能迭代 r37 中，模型把预期拒绝的越界输入放入普通成功测试批次，原 `plugin_test` 因而保持 `success=false`。该修订的独立 HTTP 验收另有六项通过，覆盖新增测试推荐、既有传递依赖和排除规则、命名导入、越界与目录联接拒绝，以及 501 个文件的截断标记。复核重新计算归档清单及 12 个源码文件的内容哈希，并逐项检查断言，确认与 r37 一致。迭代验收依据明确标为独立业务验证；原失败批次及公开输出被截断的事实均保留，不改写为模型测试成功。

Project 第三轮功能迭代的最终修订 r63 也采用独立业务验收：模型有测试调用，但没有该最终修订的成功测试批次。独立复核核对了清单及 13 个源码文件的哈希，并验证新增快照对比和此前功能的全部八项业务断言。此处记录为「没有同修订模型测试批次」，与 r37 的「模型批次失败」分别说明。

## 复现入口

- 模型全流程：`scripts/diagnostics/plugin-real-world-ai.mjs`。必须显式提供已获授权的开发 profile，使用隔离 run；`--resume` 继续原会话。
- 模型事件审计：`scripts/diagnostics/plugin-real-world-evidence.mjs`。
- 客户端验收：同级 `aether-code/scripts/diagnostics/plugin-delivery-ui.mjs`，输入明确的 ZIP 与 UI 驱动索引。
- 交付打包：`scripts/diagnostics/plugin-delivery-pack.mjs`，先 `--validate-only`，所有必需状态通过后才生成总包。

引擎本轮完整插件回归为 17 个文件、198 条通过，加上审批流回归合计 19 个文件、229 条通过，typecheck 与 build 通过。相关前端宿主回归为 10 条通过，审批展示另有 43 条纯函数与 1 条真实客户端用例通过。运行产物中的 `host-verification.json` 记录对应构建哈希。插件业务与客户端测试使用固定包哈希，后续修改任何源码都必须重新导出并验收，不沿用旧包的通过结论。

正式客户端需要包含本轮新增的 download bridge 才能使用这些页面的导出功能。独立 Node 工程可在其他 Node 环境运行，但安装到其他产品仍需其插件协议适配。Node 插件沿用已有进程执行模型，不提供操作系统权限沙箱。
