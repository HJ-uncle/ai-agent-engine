# 动态请求上下文缓存修复（2026-11-09）

## 修复

初次诊断见 [缓存前缀取证](prompt-cache-prefix-2026-11-09.md)。本次已修复生产请求组装：静态执行规则、环境解释规则保留在 system；每次更新的时间、工作区、权限、计划、交付状态与恢复提示通过独立 `requestContext` 放到历史之后。

- ReAct 主代理和子代理共享此路径，实时状态仍每次重建。
- 尾部上下文只在 adapter 序列化时加入，不写入数据库或会话 JSONL，不改变用户轮次，不把内部状态当成用户输入统计。
- OpenAI、Anthropic、Ollama 及继承实现的 DeepSeek、Qwen 均覆盖 complete 和 stream；Anthropic 将状态文本放在最后的工具结果之后，保留工具调用配对。
- 重试和 fallback 保留同一份状态。输入预算、自动压缩、收尾预留均计入尾部开销。
- system 的诊断哈希继续只反映真实 system；纠正提示标记只接受实际发送到尾部的引擎上下文。
- 前端缓存统计和公开会话协议未变，不需要调整 Aether 前端。

## 生效与边界

开发运行会固定使用启动时的引擎快照，需在当前工作结束后退出 Aether，于 `D:\dev\aether-code` 重新运行 `npm run dev`。普通页面刷新不会替换旧引擎。此修复不需要清库或迁移历史，历史用量数字不会被改写。

工具加载/卸载、真实权限或能力变化、RAG/记忆注入及必要历史压缩仍可改变部分前缀。本次解决的是每次更新时间与动态执行状态都提前破坏历史缓存的问题。
