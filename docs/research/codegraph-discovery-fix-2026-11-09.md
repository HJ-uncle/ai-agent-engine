## 原因与实现

1. `codegraph` 属于按需加载工具。注册表有此能力，但首次模型请求只提供 `load_tools` 中的工具名目录，没有可直接调用的完整定义。
2. 旧提示主要覆盖符号定位、调用关系和影响面，没有明确覆盖“深度调研整个项目”的入口。
3. 旧索引提示只在 HTTP chat 构造 system 时加入；子代理和恢复执行未统一在当前工作区边界重新发现索引。

`prepareCodegraphRequestContext(ctx)` 现在在共享 ReAct 请求边界运行，先确认当前工具权限、工作区绑定及索引文件路径边界，再探测已有索引。存在索引时只加载该注册表的 codegraph 定义，不执行查询或建图。实际查询仍由模型选择。

提示覆盖项目调研：读取适用项目规则，查询 status/files，按入口查询 search/callers/callees，再读取当前源码核对。明确目标的绝对 path；索引缺失、过期、不完整或失败时允许文本/源码检索，并禁止仅为调研自动创建或重建索引。

动态索引信息放在 `requestContext` 尾部，不进入持久化会话或静态 system。工作区切换时重新发现；进入无工具收尾时移除查询指引。只读子代理沿用自身受限 schema 和执行策略。
