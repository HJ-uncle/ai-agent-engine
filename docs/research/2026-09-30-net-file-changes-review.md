# 待确认文件改动：净变化修复与相邻逻辑审查

2026-09-30。范围：引擎文件变更记录、待确认视图、差异统计、前端保留/暂存/撤回、历史回退和引擎来源隔离。

用户截图里的 `survey.mjs` 被展示为 `+38 A` 与 `-38 D` 两条待确认记录。根因是面板直接展示操作流水，没有计算同一文件的净变化。文件原本不存在，创建后又删除，初始与最终状态完全相同，待确认计数应为零。增删行数相同本身不能作为抵消依据，内容改变仍是修改。

| 情况 | 修复后的结果 |
| --- | --- |
| 不存在→创建→删除 | 不显示待确认行，计数为零 |
| 原文件→删除→原样重建 | 不显示待确认行 |
| 原文件→删除→不同内容重建 | 一行 M，比较最初与最终内容 |
| A→B→C 连续修改 | 一行，差异 A→C；保留/撤回覆盖整组操作 |
| A→B→A | 无净变化，验证当前文件后隐藏 |
| 增删行数相同但字节不同 | 仍显示修改，包含换行和空文件存在性差异 |
| 人工修改、快照未知、状态边界、跨会话操作、路径目标变化 | 保守显示记录和提示，不猜测抵消或覆盖人工内容 |

原始操作日志和轮次快照没有删除。`GET /changes` 保留原契约，新增 `GET /changes?view=net` 返回待确认连续操作链的投影，并带有 `changeIds`、`isNew`、`projectionIssue`。前端对整组 ID 执行保留、撤回及暂存后的确认；全部撤回仍由服务端选取完整范围，不受可见行或分页限制。完整零净变化链的撤回只更新记录状态，避免临时重建、再删除文件；按某一轮历史回退的部分链仍恢复该轮边界。

同一路径遇到不能安全合并的断点时，可能分为多组并显示警告。这里的计数是待确认组数，通常一文件一组；不能为了强制“一文件一行”而跨越已确认内容或人工修改。

本轮进一步发现并修复：

| 问题 | 触发与处理 |
| --- | --- |
| 长文件统计失真 | 面板先裁剪 400 行再计数，diff 又静默截断到 800 行；现在计算保留完整输入，显示分页与统计分离 |
| 末尾换行多算一行 | `hello\n` 原计为两行；现在按实际行统计，末尾无换行单独标记 |
| 大量差异计算成本 | 剥离公共前后缀，LCS 表限制约 4 MB；超预算中段完整展示，并明确标记估算 `≈`，不显示假零 |
| 绝对路径无法暂存 | Git 返回相对路径，原服务直接与绝对路径比较；现在使用同一工作区路径标识，返回调用方原路径 |
| 路径字符被解释为模式 | 暂存筛选及 git add 使用 literal pathspec；真实验证了含方括号的文件名 |
| 暂存失败反馈缺失 | 原按钮 Promise 拒绝未写入错误状态，Git 筛选错误还被吞成空列表；现在显示真实失败 |
| 暂存成功后保留失败破坏已有 index | 移除未经快照的 git reset 补偿；保留已成功暂存的内容，说明待确认状态保存失败及重试方式 |
| 批量保留部分成功却返回成功 | 后端以单条 SQL 完整校验并原子更新；任一记录缺失、越界或已撤回，整组失败；前端核对确认数量 |
| 等锁期间状态变化 | pending 撤回等待文件锁时若记录已被保留，重新检查状态并报告冲突，不继续写文件 |
| 切换引擎后旧结果串入 | 面板按引擎代次和会话重新挂载；回退报告/卡片状态切源清空，异步链固定起始引擎身份，阻止旧结果继续截断新引擎历史 |
| 旧 Windows Unicode 路径遗漏 | SQLite NOCASE 只折叠 ASCII；按与记录器一致的路径标识匹配实际存储别名，汇总及较新操作保护使用同一匹配方式 |
| 生成过程中接受未稳定范围 | 流式生成中统一禁用面板保留、暂存和撤回，按钮提示说明暂存的是当前文件全部内容 |
