# MCP 配置与 Agent 工具链验证

## 已打通

- `/mcp/servers` 支持项目根 `?path=`，项目层 `.aether/mcp.json` 与全局层合并；显式 `MCP_CONFIG_PATH` 仍为单文件模式。
- CRUD、启用/禁用、删除、连接测试均复用同一个项目路径；更新会先按合并后的传输类型校验 URL 或 stdio 命令，禁止通过更新改 ID。
- `disabledTools` 以 MCP 原始工具名保存，注册前过滤；工具名稳定为 `mcp_<server-id>_<tool-name>`。
- Streamable HTTP/JSON-RPC：`initialize`、`notifications/initialized`、工具发现与调用；保存并回传 `Mcp-Session-Id`。旧 SSE 支持 `endpoint`/`message`/`end` 事件、POST 202 + GET 长连接、按 JSON-RPC id 匹配响应、同源校验、事件大小上限、超时和 AbortSignal 取消；每次发现/调用结束后清理连接，避免流泄漏。
- stdio：启动命令、参数、环境变量、JSON-RPC 初始化/发现/调用；支持换行和 Content-Length 帧，工具调用结束后关闭子进程，避免每次对话泄漏进程。
- 请求级 inline MCP 同样支持 stdio，凭据只存在本次 registry 生命周期，不写入 `mcp.json`。
- 聊天 registry 可接收 `workspaceRoot`，真实 `/chat` 调用传入 `workspacePaths[0]`，因此不会只读取引擎工作目录。

## 当前边界

stdio 与 HTTP 调用均受安全模式和网络策略保护。认证开启时资源管理 API 要求登录或 `admin`/`skill-manager` 角色；本地开发 E2E 显式使用 `AUTH_ENABLED=false`。Windows 下运行进程树测试需要提升权限；普通沙箱会出现 `taskkill`/WMI 拒绝或 `uv_os_get_passwd ENOMEM`，提升权限后的最终结果才是本报告的全量结论。
