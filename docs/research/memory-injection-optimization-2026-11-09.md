# 记忆注入优化与三轮真实开关对照

日期：2026-11-09。

## 已实现

- 数据库召回及客户端内联记忆统一移到历史后的临时 requestContext；system 仅保留固定使用规则。临时参考不会持久化为用户消息。
- 两条路径共用约 2000 个估算 tokens 的上限，并保留小窗口 8% 约束、Unicode 完整性和省略提示；数据库原文保留。
- 空授权库、精确寒暄和禁用状态跳过召回模型请求；直接命中优先、排序确定、图候选查询有界。
- 历史向量补齐改为回答后的维护，每 scope 最多 20 条，并发去重、失败 60 秒退避，退避表最多 128 项。
- 编辑和重新生成入口同步采用尾部上下文；修复重新生成因没有追加用户消息而完全跳过记忆召回的问题。
- router/extraction 按物理请求单独观察输入、输出、缓存、失败、未知用量与耗时；主请求 usage 帧附带辅助统计快照，后台完成用量写入结构化日志。
- 修正辅助统计的 Anthropic 口径：总输入减缓存读取才是全部未命中输入；provider 的 cache-creation/write 原计数另行保留。缺失缓存数据标记 unknown/null，不伪造零。

主要实现：`src/core/memory-request-context.ts`、`src/core/chat-system-prompt.ts`、`src/core/agent-loop/react.ts`、`src/api/http/routes/chat.ts`、`src/api/http/routes/messages.ts`、`src/middleware/memory/extractor.ts`、`src/middleware/memory/usage.ts`、`src/storage/memory/memory-manager.ts`。

## 内容、存储与限制

- 两组第二轮均沿用旧偏好，第三轮均应用新偏好。关闭组仍有完整聊天历史，回答正确不能作为长期记忆生效的证据。
- 确认轮第三轮开启组严格格式通过，关闭组附加记忆说明而失败；诊断轮两组都附加说明。严格格式表现存在波动，不能报告全部通过。
- 关闭组曾声称会话关闭后信息不会留存，与持久聊天历史不一致。这是模型表述问题；关闭记忆不等于删除历史。
- 开启组节点 1→3→4，第二轮提取出语义重叠条目；旧偏好继续保留、更正另存新节点。语义去重、冲突版本替代尚未解决，当前响应依靠最新请求优先规则。
- 开启组 4 条记忆正文总共 192 字符/494 UTF-8 bytes，无向量。共享记忆库主文件 4096、WAL 865232、SHM 32768 bytes；902096 bytes 的物理占用含 schema/index/WAL/页开销，不能视为某组独占的正文量。
- 未采样 CPU/RSS，不据存储字节推断内存或 CPU 变化。
- 本轮未引入 TTL 召回缓存。运行中关闭/删除后撤回已经注入的当前快照、子代理自动记忆与根会话统一，仍属独立待完善能力。
- 这是小样本观察，不是严格缓存因果实验。两组工具能力和后续历史不同，上游可能跨会话共享缓存并相互预热。

引擎注入优化不要求修改 Aether 的现有界面；新增辅助统计目前用于协议与日志，前端尚未新增其展示。正在运行的应用需要重新加载新的引擎构建。
