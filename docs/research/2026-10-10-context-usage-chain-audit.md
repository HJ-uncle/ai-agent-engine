# 上下文用量跳变：全链路排查与修复

日期：2026-10-10。范围：`D:\dev\ai-agent-engine`、`D:\dev\aether-code`。

后续本地截图核查与补充显示修复见 [本地上下文显示精度核查](./2026-10-10-local-context-precision-audit.md)：14,577 → 14,589 → 14,605 在原显示精度下均为 14.6K；已补精确整数、请求中更新与输入来源标记。该后续最终回归为引擎 506 项、客户端 67 项，构建身份见后续报告。

## 数字应如何理解

截图展示的是“上下文窗口”的使用量和上限。它表示最近一次模型调用的输入占用，不是用户这一轮请求的累计输入。一次用户请求可以包含多次模型调用：工具输出使下一次输入变大；自动压缩、工具结果清理、关闭历史继承等可以使下一次输入变小。不能用累计计费输入除以上下文窗口来显示占用百分比。

| 口径 | 示例 | 是否可以下降 |
| --- | --- | --- |
| 最近一次调用的输入上下文 `currentPromptTokens` | 12K → 22K → 10K | 可以，压缩等改变实际输入 |
| 当前用户轮次的累计输入 `promptTokens`，SSE `usageScope: turn` | 12K → 34K → 44K | 同一轮中不应因压缩或审批恢复下降 |
| 持久化 assistant 行的 `usage.promptTokens` | 分别保存 12K、22K、10K | 每行是调用增量，不能写成上述累计值 |
| 会话已保留调用总量 `sessionUsage` | 完整历史调用增量之和 | 不应因分页、压缩或刷新下降；主动删除历史可以减少 |
| 子 Agent 用量 | 按子运行 ID 去重后另计 | 不加入父模型的上下文占用 |

截图本身不能证明是哪条代码路径触发了某一次下降。本轮以代码、可失败的复现断言和回归测试确认以下真实缺陷；没有将所有上下文下降都判为错误。

## 已修复的链路问题

1. **模型请求估算重复计算。** ReAct 原先将历史里的工具结果再累加，并沿用首轮工具定义估算。改为按本次真正发送的消息、工具和附件计算；已归档的工具结果不再进入当前分项。用户输入按最后一条 user 查找，避免末尾是 tool 时计成零。分项舍入后严格加和到本次输入总量，Skills 不再同时算入系统提示和技能分项。
2. **当前输入、累计输入与旧模型窗口混用。** 历史恢复和流投影现在分别维护当前输入与累计输入。新输入没有上限时不会继承旧上限；`contextModelId` 将输入快照与所属模型配对，后来的仅模型更新不改写已有输入归属。`usageScope: turn` 缺少当前输入时不会把轮次累计当作上下文。
3. **自动 fallback 后窗口错误。** 备用模型使用其有效容量与请求容量的较小值，并将窗口随实际调用传入实时和历史统计。Code 模式的输出余量随较小窗口调整，不沿用主模型的较大输出余量。显式输出约束仍需能够装入模型窗口。
4. **审批恢复让累计计数归零。** 为同一个持久轮次保存前序调用基线，每次 attempt 的累计帧只加该固定基线一次。压缩过的前序行也从完整计费记录恢复。SSE 携带 session/run/turn/attempt 身份。
5. **压缩删除历史用量。** JSONL 改为读取完整归档中的已保留计数，不使用压缩后的消息长度代替供应商用量；缓存检查文件 revision，追加增量维护，编辑、删除和外部写入会失效。SQLite 增加独立 `conversation_usage_archive`，在同一事务里保留计数并重建上下文，失败则整体回滚。
6. **清理孤立前缀和迁移丢失用量。** SQLite 孤立消息删除前先原子保留计数；旧库缺少消息 ID 的行补稳定 ID。SQLite → JSONL 迁移生成隐藏 usage receipt，保留删除键和轮次键，不加入模型历史、用户归档分页或搜索。重复压缩、迁移和追加不会重复计数。
7. **持久化领先 SSE，刷新重复或漏记。** 主统计使用同一事件水位的“已持久化其他轮次 + 已发布当前轮次”；子统计与 `subagentRuns` 明细同源。客户端建立权威基线，按父消息和子运行 ID 计算之后的增量，不从当前可见历史重新算全会话费用。
8. **长轮次裁剪造成统计倒退。** 超过 4096 个投影槽时保留最新 usage 和 run 控制态。子运行仅在内存保存已发布的 ID/seq，按不可变事件批量恢复对应快照，既不丢失已发布费用，也不读取数据库里尚未发布的未来费用。纯工具流同样执行裁剪；恢复时保留已有裁剪标记。
9. **长审批历史挤掉最新待答项。** run 投影保留所有活跃待答项，剩余空间保存最近已答项，旧已答审计仍在持久化存储中。
10. **兼容模型 usage 解析不一致。** Qwen/OpenAI 兼容路径统一解析 `prompt_tokens/input_tokens`、`completion_tokens/output_tokens`、缓存和推理字段。分段 usage 只合并已报告字段，显式零保持为零，不累加重复累计快照；不再用最后一段覆盖前面输入统计。
11. **断流与缺失字段被当成零。** 已收到的 usage 立即交给 ReAct；只有缺失的字段才估算，显式零不会被 `||` 替换。只有工具参数、尚无正文时中断，也会保存已发生调用的估算用量。成功和部分响应的估算来源记在单行 `metadata.usageEstimated`。子 Agent 物理调用记录保留已知下界，缺少输入或输出时标记 `unknown`，不会把缺失数据宣称为完整费用。
12. **客户端交互及 CRUD 同步。** 修复模型菜单选完不关闭、压缩回调跨会话覆盖状态、提示卡拦截输入框点击。删除、重试和回退后重新取得权威统计，迟到响应不能覆盖其他会话；未知子用量转已知后同步清理未知标志。轮数标签明确为“已加载用户轮次”。

## 证据范围和生效方式

- 适配器测试使用真实 SDK 与受控 HTTP/SSE 响应，覆盖四个指定模型的协议路径；不等同于四家在线模型的新一轮付费压测。
- 客户端的真实 Electron 远程交互使用受控 API 夹具；引擎另有真实 HTTP 路由、JSONL 文件与 SQLite 测试，不把前端夹具当成正式数据库落盘证据。
- 已在旧 SQLite 压缩中被永久删除、且没有其他账单或归档的用量，不能凭空补回。新账本保证之后的压缩不会重复丢失。
- 主用量缺失时存在本地估算；估算标记目前保存在单条历史元数据，累计 UI 没有聚合展示该标记。会话展示值不能当成供应商结算发票。
- 本轮没有中断或重启用户会话、没有启动新的收费五会话长测；不以本次回归宣称 5–6 小时或 7×24 小时已经验收。
- 两端源码和构建产物完成后，运行中的旧引擎进程仍需在合适时机重新加载，才使用这次修复。开发客户端的本地引擎加载路径是兄弟目录 `ai-agent-engine/dist/main.js`；远程实例需更新其部署产物并重新加载该实例。
