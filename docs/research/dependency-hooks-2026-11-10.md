# 子代理依赖钩子：实现与验证

日期：2026-11-10。引擎：`D:\dev\ai-agent-engine`；Work 前端：`D:\dev\aether-code`。

## 行为

主模型先声明后续工作的依赖组，系统收集子代理终态。只有整组成功，或者出现需要处理的失败，才让该组进入下一次主模型请求。等待期间没有模型定时轮询；主模型忙碌时只收集状态，不启动另一个并行主模型。

用户提出的例子已经实现：A 依赖 1，B 依赖 2、3。

| 事件 | 主模型行为 | 固定响应集成测试中的累计请求数 |
| --- | --- | ---: |
| 登记计划、启动子代理、主动让出执行 | 系统等待 | 1 |
| 2 先完成 | 记录结果，B 仍不齐；正文不进入主模型输入 | 1 |
| 1 完成 | 唤醒处理 A | 2 |
| 处理 A 时 3 完成 | 记录 B 就绪，不并发调用主模型 | 2 |
| A 当前响应结束 | 下一请求带齐 B 的结果 | 3 |

多个组在同一请求边界就绪时合并通知。结果在同一个请求里按 runId 去重；这不意味着所有后续请求都不再携带历史上下文。

## 工具协议

`plan_update` 在现有完整计划协议上增加三个字段：

```json
{
  "plan": [
    { "step": "集成 A", "status": "pending", "wakeWhen": { "allSucceeded": ["task:one"] } },
    { "step": "集成 B", "status": "pending", "wakeWhen": { "allSucceeded": ["task:two", "task:three"] } }
  ],
  "awaitDependencies": true
}
```

- `wakeWhen.allSucceeded` 接受当前执行拥有的真实 runId，或 `task:<key>`。
- 同一批 `subagent_start` 使用对应的 `taskKey`，避免为了获取 runId 单独增加模型请求。
- `awaitDependencies: true` 表示当前没有可独立推进的工作。整批工具执行完后才进入系统等待，因此不会阻塞同批子代理启动。
- 更新已有步骤沿用返回的 id；`expectedRevision` 可拒绝过期修改并返回当前计划。
- `wakeWhen` 省略保留，显式 `null` 解除；删除步骤或取消步骤同步废弃该依赖。
- 每个执行最多 32 个活跃组，每组最多 32 个引用。runId 和 taskKey 指向同一子代理时，进度只计一次。

任务键按当前 root/attempt 隔离。相同调用与相同参数的重试复用启动回执；换调用、换参数或换绑到另一个 run 会被拒绝。已完成子代理的续作仍沿用原有恢复功能；钩子绑定本次实际执行的 runId，不能用旧成功结果代替新执行。

## 状态、持久化与调度

钩子状态为 `armed → ready/blocked → consumed`，另外保留 `cancelled/superseded`。`ready` 只表示后续工作可以开始，不会自动把任务计划标为完成。`consumed` 表示模型已经收到该通知并产生完整有效响应，不表示产物已验收。

新增五张小型表存放作用域、钩子、任务键绑定、完成回执与计划条件；没有复制子代理对话正文。删除 root 会级联清除这些新增元数据。内存只保存活动订阅、执行器观察与本次等待标记。

完成条件必须同时满足真实执行器结束、终态序号匹配、投影回执确认、协作 ticket 完成。单独把数据库状态改为 succeeded 不能触发成功条件。事务前后校验 tenant/session/root/attempt/generation 与执行所有者，旧执行没有更新权限。

观察同时订阅子代理完成、计划变更和已接纳的协作消息，订阅之后再核对版本，避免丢失唤醒。取消只结束观察并清理订阅；整个运行仍走原有取消与收尾协议。

进程重启保留计划与审计数据，但不自动恢复旧 attempt 的执行权限或重新派发任务。新执行需要基于当前任务重新登记依赖。

## 输入隔离与收尾

- 尚未就绪的 managed 结果留在持久历史中，从主模型请求投影中隐藏。
- 自动压缩也使用同样的纯过滤规则，不把半齐结果写入摘要，不注入或消费钩子通知。齐全后可从已完成执行器的结果恢复必要证据。
- 压缩依据已授权执行记录保留仍待结果投影的子代理启动记录及接纳回执，防止晚到结果因启动记录消失而被抑制。结果投影确认后才可正常压缩这些记录；不会重建用户明确删除的记录。
- 被删除启动记录所抑制的结果不能通过补读重新出现；独立保存每个 run 的抑制状态，避免一组多个失败时漏掉后来的抑制结果。
- 失败组先给一次异常通知；异常消费后，仍运行的正常同组子代理完成时仍需要验收。被抑制的 run 不会重新补读。
- provider 报错、空响应或截断响应不会提前消费通知；有效完整响应后才确认消费。
- 模型在依赖未齐时输出的纯文本候选回答先保留为模型草稿，不提前展示为交付。验证放行后才公开；截断续写在实时显示、历史回放中保持完整，模型历史不重复放入续写前缀。
- 未使用钩子的旧调用保留原有等待和收尾兼容路径。

## Work 前端

RootRun 增加有界的 `activity` 字段，包含等待/执行阶段和每组计数。等待子代理时 root 状态仍是 running，停止操作保持可用。

前端在现有运行反馈与左侧列表状态中显示依赖进度，不增加反复的等待工具卡。实时 run 事件、HTTP 状态查询、快照恢复都传递该状态；取消、问答、终态和断线状态按原有优先级显示。深浅主题、小窗口和长步骤名称已覆盖组件验证。
