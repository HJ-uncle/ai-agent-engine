# 账号登录与恢复

源码核对：2026-11-23。桌面入口与新用户操作见[账号与登录](../../aether-code/docs/accounts-and-login.md)；本页说明引擎协议与身份边界。

账号接口位于引擎根路径 `/auth/account`，使用标准 `{code:200,data,...}` 响应。配置实例令牌时，除明确放行的探针、管理页静态资源和浏览器第三方回调外，受保护请求仍须携带 `X-Aether-Instance-Token`。远程生产部署必须使用 HTTPS，实例令牌不是用户身份。

## 自建服务：实例令牌与高级用户凭据

本机内置引擎由桌面自动生成、传入实例令牌。自建服务可在桌面「连接其他引擎 → 高级设置」生成随机实例令牌，也可由部署者在本地生成独立的 32 字节随机值。将同一值放入服务端启动配置 `AETHER_INSTANCE_TOKEN` 并重启该服务，再在客户端应用连接。桌面连接非回环地址需要提供实例令牌。仅当地址是 `localhost`、`127.0.0.1` 或 `[::1]`，且独立服务未启用此项校验时，桌面才允许留空。独立服务未配置令牌时不会核验该值，因此客户端连通本身不能证明服务端已启用令牌校验。生成值不会远程修改服务器。独立引擎不会在未配置时自动创建令牌，启动日志也不打印原值。管理员可在随服务启动的同端口 `/admin/` 核对运行状态；详见[后台、首次管理员与本机查看令牌](operations/engine-admin.md)。

使用个人账号登录无需填写高级用户凭据。使用旧式 API Key 时，桌面生成的是候选值；如需登记候选值，独立服务要求调用 `POST /auth/user` 的身份属于同一租户且具有 `admin` 角色。新登记的 API Key 必须是 1–4096 个不含空白的可见 ASCII 字符；无效输入不会替换旧值。接口以摘要保存密钥，对已有租户成功登记新值会替换原 API Key。全新默认租户可使用[离线初始化脚本](../scripts/provision-default-admin.mjs)创建首个管理员密钥，脚本不覆盖已有用户。JWT 由服务认可的签发方签发；`JWT_SECRET` 是部署端验签密钥，不应填入客户端。

## 用户入口

- `POST /register {activationCode}` 使用本服务后台签发的开通码新建主账号，生成随机名称、内部 userId、独立 tenantId、恢复凭证与账号会话。`AETHER_ACCOUNT_REGISTRATION=false` 关闭公开注册（包括第三方首次开通）。可选个人信息通过登录后的 profile 保存；不要求填写密码或邮箱。创建新账号与登录已有账号是不同操作。
- `POST /activation {activationCode}` 让已有独立个人账号在原数据空间启用主账号。要求该账号近期验证的会话；子账号不能使用。已开通时不会消耗第二个码。
- 开通码有效期 7 天，只能使用一次。服务端只保存摘要；开通码不能用于登录、恢复或获得管理权限。无效、过期、撤销的码都不能开户。账号创建和开通码兑换在同一事务提交；已有登录不受其他人领取新码影响。
- `POST /login {recoveryKey}` 使用恢复凭证重登；也接受已存在有效 API Key，保留旧用户 ID、租户及所有租户数据。不会把匿名 default 数据自动归给新账号。
- `GET /me` 读取个人资料、已绑定身份、当前会话 ID、可信存储中的 `roles` 及本会话最近真实验证时间 `authenticatedAt`（ISO 8601）。后两者不从用户填写的 `userData` 读取。
- `PATCH /profile {name?,email?,avatarUrl?,bio?,userData?}` 更新资料；省略 name 保持原名称，显式空值或空白名称生成随机名称。userData 限 16 KB JSON 对象，不能修改角色、内部 ID 或租户。邮箱为用户自填资料，不代表邮箱验证。
- `POST /refresh {refreshToken,requestId?}` 更新短期访问凭证。
- `POST /reauth {recoveryKey}` 在当前有效账号会话内重新验证。恢复码或旧 API Key 必须属于当前用户，错误凭证返回 403，不注销当前账号；成功返回 `AccountUser`，只更新当前会话的 `authenticatedAt`，不更换用户/租户/令牌、不新建会话、不延长 30 天总有效期，也不更新其他会话的验证时间。每个来源地址每分钟最多 10 次。未登录或原会话已失效返回 401。
- `GET /sessions`、`DELETE /sessions/:id` 查看或撤销自己的登录会话。
- `POST /logout {all?:boolean}` 注销当前会话或全部会话。
- `POST /recovery {}` 轮换恢复凭证，并撤销其他会话及旧 API Key；须在本次登录认证后 10 分钟内执行。新的恢复凭证只返回一次。
- `DELETE /identities/:providerId` 解绑第三方，须在本次认证后 10 分钟内执行，且不能删除最后的可用登录方式。

恢复文件仅携带访问已有账号所需的恢复凭证，不是会话、工作区文件或引擎数据库备份。恢复只会查询当前所连接引擎的数据；独立新引擎没有原账号记录时不能凭恢复文件重建账号数据。首次注册也不会把匿名 `default` 租户的数据自动迁移到新账号。

## 主账号与子账号

一个服务内只有两层关系。后台签发的开通码决定谁能成为主账号；子账号只能由已开通的主账号创建，一个子账号只有一个所属主账号。主账号默认有 **3 个子账号名额**，自身不计入。停用会保留子账号的数据和名额；管理员可在[管理后台](operations/engine-admin.md)按主账号调整上限。

以下路径相对于 `/auth/account`。接口从当前账号会话确定主账号身份，不接受客户端指定父账号、租户、角色或额度。

| 请求 | 结果 |
| --- | --- |
| `GET /children` | 返回 `{limit,used,children}`，只包含自己的子账号。 |
| `POST /children {name}` | 创建独立的子账号及其数据空间，不需要开通码。并发创建也不能超过配额；已满返回 `409`。 |
| `PATCH /children/:id {status}` | `disabled` 停用并撤销该子账号的会话，`active` 恢复可用；恢复后旧会话不复活。 |
| `POST /children/:id/enter {}` | 签发只属于该子账号的会话。它受发起的主账号会话约束，不向子账号传递主账号凭据。 |

子账号使用安全模式，工作区限于自己的空间或服务允许且未被其他账号绑定的项目。即使主账号在本机使用完全访问，或桌面服务无需强制登录，子账号也不继承这些权限。

子账号无论如何登录，访问家庭管理接口均无权，拿到主账号开通码也不能把自己升级。一个主账号不能进入或修改另一个主账号的子账号。个人主账号身份也不自带实例后台权限。旧版创建的独立个人账号可先用原方式登录，再用开通码原地启用，保留原账号、租户和历史。

## 当前会话重新验证

重置恢复码、绑定或解绑第三方前，可以使用 `POST /reauth` 完成验证后重试原操作，无需先退出账号。`refresh` 只维护短期令牌，不刷新 `authenticatedAt`，不会绕过敏感操作的 10 分钟认证要求。

第三方 `/external/start` 与 `/external/credential` 支持 `mode: 'login' | 'link' | 'reauth'`。`reauth` 必须从有效账号会话发起，仅接受已绑定当前用户的精确 `(providerId,issuer,subject)`，不能借机新建账号、绑定新身份或切换用户。浏览器回调与结果领取都重新检查原会话未撤销且未到期；`/external/poll` 还必须携带发起时同一账号会话的 Bearer。返回 `{status:'complete',result:AccountUser}`，不是新的令牌对。credential 模式直接返回 `AccountUser`。`link` 仍要求近期认证，且保持原来的绑定语义。

## 使用技能与管理技能

`GET /api/v1/skills?available=1` 是输入菜单使用的运行时可用技能目录，普通已登录账号也可读取；它仍遵守启用状态和 OSM 过滤。显式 `path` 必须通过现有工作区权限校验：鉴权部署中限制为允许的工作区且不得属于其他租户。本地单机继续允许选择本机工作区。目录读取不跟随越过授权项目的技能目录联接点或 manifest 路径；不传 `path` 时只返回共享/部署/内置技能，不暴露服务器 cwd 的项目技能，也不返回管理路径。

默认技能管理列表、详情、导入与写操作仍要求 `admin` 或 `skill-manager`，`available=1` 不会放开这些接口。账号会话的角色来自后端可信配置，前端显示角色不能授予权限。

技能目录响应和 `GET /api/v1/settings` 在原有字段外增加 `permissions: {canManage:boolean}`。该值与对应写接口共用角色判断：技能管理要求 `admin`/`skill-manager`，设置写入要求 `admin`，本地匿名保持原有放行语义。前端应据此展示管理操作或只读状态，不能因为未获取 AccountUser（如使用 API Key/JWT）就推断为无权限；服务端仍独立检查每次写入。

## 子账号密码

主账号在自己名下的启用子账号上设置服务内唯一的登录名和初始密码。已配置的子账号可以独立登录、修改自己的密码，也可以先用当前密码生成一次性找回码。找回码不授予登录权限，服务仅保存其摘要。普通个人账号的恢复码、后台密钥、其他账号的凭据不能用于此流程。

以下路径相对于 `/auth/account/child-password`，所有写请求发送 JSON，凭据不要放入 URL：

| 路径 | 用途 |
| --- | --- |
| `GET /children/:id`、`PUT /children/:id` | 所属主账号读取登录名，或更改 `loginName`、`password`；写入要求近期验证。密码和恢复码均不回显。 |
| `POST /login` | 使用 `loginName`、`password` 登录启用的子账号，签发该子账号的独立会话。 |
| `GET /me`、`POST /me` | 子账号读取自己的登录名，或提交 `newPassword` 及唯一一项身份证明：`currentPassword` 或 `recoveryKey`。保留当前会话，撤销其他会话。 |
| `POST /reset-code` | 子账号提交 `currentPassword`，签发一次性密码恢复码。只在这次响应返回新码，上一枚作废。 |
| `POST /recover` | 未登录时，提交 `loginName`、`recoveryKey` 和 `newPassword`。成功后一次性码作废、所有原会话退出，需要用新密码重新登录。 |

主账号改名或重置密码会撤销目标子账号会话；重置密码还会撤销其旧密码恢复码。其他账号及各自的数据保持不变。子账号停用期间不能用密码或找回码访问。远端部署应通过与个人账号相同的受信传输访问。

## 会话边界

成功登录返回 `{user,accessToken,refreshToken,expiresAt,recoveryKey?}`。时间字段为 ISO 8601。访问令牌为 `aether_session_` 加 256 位随机值，15 分钟过期；刷新凭证为独立 256 位随机值。会话固定有效期 30 天，届时需重登。数据库仅存恢复、访问与刷新凭证的 SHA-256 哈希。

每次刷新原子消费旧 refreshToken 并签发新凭证。原 accessToken 保留至其原定到期时间，避免轮换时打断已发出的请求；注销、会话到期或重放撤销仍立即使该会话的所有访问凭证失效。已到期的历史 access 哈希在该会话下次刷新时清理。客户端为每次刷新生成随机 requestId，先保存后发送，并使用单飞请求。同一旧 refreshToken + 同一 requestId 可在 5 分钟内重试并取得原结果，包括服务端重启后；缓存用旧明文 refreshToken 通过独立域派生 AES-GCM 密钥加密，数据库哈希不能用于解密。换用不同 requestId 重放旧凭证、超过重试窗口，或不带 requestId 重放会撤销该会话。正常临时网络错误不应清空本地凭证；客户端保留待完成 requestId 重试即可。

AUTH_ENABLED=false 只允许缺少凭证的本地匿名请求继续使用 default 租户；显式提交的账号会话仍会验证，错误凭证不会降级成匿名。旧 API Key 和 JWT 的既有业务认证保留；新账号管理接口只接受可撤销的本系统账号会话，旧 API Key 须经 login 换取账号会话。第三方须经可信适配器验证后调用内部身份映射服务，客户端不能指定自己要绑定的内部 userId。

第三方唯一身份为 `(providerId, issuer, subject)`。登录已有绑定会复用同一内部用户；登录新身份会创建新账号。绑定仅限已登录且最近认证的账号，保留原 userId 与 tenantId，不按邮箱自动合并。第三方身份的 name、email、avatarUrl 单独保存并随已验证登录更新，自定义 userData 保持独立；绑定不覆盖用户的本地个人资料。已绑定其他用户时返回冲突，避免隐式数据归属转移。

新开通的主账号初始只有 `tenant-admin`：可管理属于自己租户的模型及 safe/standard 会话安全模式；远程 full-access 仍需实例管理员。由桌面持有实例令牌的本机 loopback 引擎允许自己的账号使用会话 full-access，这不授予实例管理角色。实例级设置、安全策略、全局 Skills 等仍要求管理员。自定义资料和第三方 userData 不参与权限判断。

本地 SQLite 写事务使用认证模块共享队列，避免并发首次登录/刷新/回调互相争锁；数据库唯一约束与事务仍是最终数据一致性保障。登录端点按来源地址限速，计数持久化；应用默认不信任代理转发的来源地址。部署在反向代理后，需要由运维明确配置可信代理与入口限速。

会话及审计历史未启用自动删除；刷新结果虽只有 5 分钟可重试，数据库保留其密文，历史保留策略需由部署方决定。主账号使用恢复凭证或绑定的第三方身份登录；子账号密码见下节。服务目前不提供 SCIM 目录同步、邮箱验证或内置多因素认证。
