## 修复顺序与复验要求

1. **统一数据库写入协调并确保连接配置生效。** root 取消、子 Agent 快照、历史保存等写入需要共同遵守事务边界，避免多个连接争用。对物理连接初始化、事务后重连、并发取消与写快照添加回归。不能仅把同步客户端的 busy_timeout 调大，否则可能将锁等待变成更长的事件循环阻塞。
2. **定位响应尾延迟。** 采集事件循环延迟、SQLite 调用耗时、GC、服务端收到请求与完成响应时间，再用相同 5 会话负载 A/B 验证。验收需同时检查 HTTP 状态、业务返回码、任务落库及清理状态。
3. **改善子 Agent 重试提示与收尾。** 区分代码失败、审阅失败和测试预算截止；代码已验收时只补失败审阅，明确当前轮状态，避免复述旧失败。实际核验并发派发，不能仅凭提示词声称已经并行。6 步 / 180 秒是本轮测试约束，不应直接当成产品缺陷。

修复后需要重跑相同长时负载；本报告不代表这些产品修复已经完成，也不代表 Electron UI、MCP、Skill、知识库、远端网络或所有产品功能已被本轮覆盖。
