# 解释器参数误拦截：待批准的策略修改

当前真实长测会话执行 `node -e`，源码仅解析 URL 并输出参数。执行器通过 `shell:false` 传入 argv，但策略看到源码中的分号后要求确认，导致后台任务等待。已审查并确认这一次调用；该确认不改变策略。

拟修改范围：仅在用户选择的 `standard` 模式，直接 Node/Python/PyPy 解释器的 argv 不再按 shell 元字符扫描。解释器运行任意源码的能力仍来自 standard 模式本身。安全模式继续原检测和逐次确认；shell、包管理器包装命令、文件删除与审计规则保持原样。

风险：standard 模式的解释器代码拥有宿主文件和网络访问能力，参数中也可以通过代码启动子进程。此修改降低标准模式下的额外确认频率，不能把它称为沙盒。自动审批拒绝了该持久化修改，理由是扫描豁免范围超出已审查的单条命令。此文件仅记录提案，未执行修改。

批准后验收：真实 Node URL/模板字符串/比较符 argv 正常执行；safe 模式继续拦截；shell 元字符仍需确认；删除命令仍走当前删除规则；两端类型检查及完整测试。
