# 长时开发测试的后续准入条件

此文是 R4 运行期间对后续 4–5 小时和 7×24 小时任务的准备记录，不是完成报告。正式项目保留在 `D:\dev\ai-agent-engine\test-projects\longrun-20261009`。不得把预算上限、依赖等待或人为休眠计作实际开发负载。

## 先完成当前双端验收

1. R4 五十阶段的真实红转绿开发、父 Agent 测试、当前代码子评审、父复测和独立复验全部留存；失败原样保留。
2. 客户端编译后的真实五会话切换、模型显示、刷新和续聊请求一致；同会话排队项更新，不串其他会话或其他引擎来源。
3. 两项目真实浏览器 / HTTP CRUD、持久化重启、保存视图与库存盘点通过；项目数据和源码保留。
4. 终态独立检查实际三 Qwen / 两 DeepSeek、workspace 三加二、运行重叠、健康、数据库、资源采样连续性、产物冻结身份与清理。
5. 新冻结引擎的客户端完整轮单独记录。历史旧包全绿、当前专项通过和正式负载通过分别报告。

## 4–5 小时开发轮

在当前项目上增加真实需求，不清空成熟源码。建议 ops-board 开发离线 outbox、冲突预览、跨窗口同步和任务附件；ledger-api 开发多仓库存、预留过期、分页、订阅及恢复。先冻结每阶段合同和完整失败基线，再发给对应角色。

每里程碑都验新功能、旧完整基线、子 Agent 评审、父复测和真实界面。同项目并发写入应覆盖 CAS 冲突及重新读取，不能仅靠文件职责分离规避所有共享状态冲突。保留任务开始 / 结束、依赖等待及 root 真正 running 区间，并分别报告五路、四路、三路重叠时长。

按真实 SSE / command job / 数据库证据统计吞吐、重试、取消、压缩、模型错误和命令残留。健康成功率和延迟分阶段统计；资源曲线按活跃负载、空闲回收、历史增长分别解释，不以一次峰值推出容量。引擎进程树采样不能代表整台服务器或 Electron 总开销。

## 7×24 小时开发轮

当前两小时 harness 的超时 / 最大尝试和根任务保留方式不能直接等同于七天可靠性。有限的五会话十阶段全部完成就退出，提高 LONGRUN_MAX_MINUTES 不会自动产生持续开发。monitor.ps1 的 MaxMinutes 上限为 1440，编排器还增加二十一分钟收尾预算；直接配置二十四小时或七天，监控分别收到 1461 / 10101 分钟并被参数校验拒绝。需要基于可恢复里程碑的运行器、独立状态库和明确费用预算，不能将单次请求挂七天。

现有并发门要求 allFiveOverlapMs 大于零，未约束持续时长或覆盖比例；资源检查主要报告峰值和错误，未预先设置采样断档率、内存 / 句柄增长斜率与资源预算。analyzer 整文件加载 JSONL；客户端归档验收默认最多 20000 行、界面最多二十次加载。长时验收前需要扩大并验证这些边界，不能将脚本上限当作用户历史上限。

开始前至少完成：

- 完整会话请求参数的无凭据回读契约，客户端按 source / session / run version 恢复并验迟到响应。
- 聊天协议与记忆 embedding 服务解耦。本轮 Anthropic 兼容聊天路径正常，但向量生成不支持，记忆降级关键词 / 图召回。需支持独立向量配置、维度与模型一致性、可恢复回填，并真实验语义召回及租户 / 会话隔离；不能仅关闭告警就计为修复。
- 明确进程重启策略。当前 RootRunStore 会将运行中 root 标记 interrupted，不自动恢复；继续任务必须显式建立新尝试，并检验原操作是否已提交。
- 为重复执行定义幂等键和 checkpoint，验证写盘成功但响应断开、子 Agent 失败、模型超时、数据库写冲突与命令取消后的恢复。
- 按实际任务量验证 JSONL / 数据库 / command retention。每会话 100、全局 500 的命令留存可早于验收清理证据；完整原 SSE 与输出另存，并检测矛盾记录。
- 采样、日志和证据支持轮换，磁盘容量预警、每日快照及完整恢复演练，避免测试本身耗尽磁盘。
- 对 Windows 睡眠恢复、网络中断、模型切换、工作区删除或移动、服务重启进行单独故障注入；每次保留触发点与恢复结果。
- 如果通过多租户 Cron 派发，先实现可信 tenant dispatcher，并完成同名资源跨租户负向测试。当前单机实例 token 不能代替用户或租户身份。
- scheduler / server stop 必须取消或等待其 owned in-flight jobs，阻止重复 tick 重叠；当前 fireJob 的 120 秒请求超时也不是长任务恢复机制。

七天轮必须记录实际有效开发时长、每日报告、原失败和终态清理。未运行的故障条件标为未验证；仅当七天真实执行及所有里程碑验收结束后，才能报告该持续时间通过。
