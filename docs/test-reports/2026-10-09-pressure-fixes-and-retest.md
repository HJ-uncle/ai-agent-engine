## 本轮修复范围

1. 主业务 SQLite 的原生调用最终采用独立 **Node 子进程 + 单一物理连接**，普通请求和交互事务按连接顺序执行；事务自身操作可以继续运行，commit/rollback/close 释放队列。避免 libsql 原事务接口分离连接导致的连接参数丢失与原生连接 GC 风险。IPC 使用 advanced 序列化，保留 bigint 与二进制数据，连接配置只走 IPC。
2. 数据库初始化共用进行中的 Promise，失败可重试；关闭、立即重连、连续重连、旧事务失效及 ESM CLI 启动都有回归覆盖。父进程退出/被强杀后子进程清理退出；数据库子进程异常退出使待决操作明确失败，宿主保持存活。保持现有 Client 调用形态和 HTTP/SSE 协议，不要求前端修改请求。
3. `/chat/cancel` 在数据库状态写入失败时仍执行命令进程清理，保留失败响应供客户端识别与重试；重试可补齐根任务终态。没有把 HTTP 200 的失败业务响应改成假成功。
4. 子 Agent 工具结果增加当前 runId、parentToolCallId、机器状态和错误码，模型正文不能覆盖失败状态；子任务原始 resultSummary/partialOutput 保留，父任务工具结果正文增加机器状态头，前端结构化协议未改。提示词要求区分当前调用与历史失败、按实际工具批次描述并行、明确未完成部分。
5. 全量回归额外发现终端窄视图长文件名被挤到极窄列，恢复堆叠显示；保留已有紧凑表格与分隔线设计，更新不再适用的旧断言。
6. 开发模型迁移改为在私有连接上显式 BEGIN/COMMIT/ROLLBACK，读源使用只读事务，保证连接所有权与释放；不修改源数据库或将密钥写入测试报告。

同类路径排查确认独立 memory.db 的标签重写和批写也使用 libsql 原事务接口，已纳入本轮修复；知识库没有相同事务分离调用，暂不调整架构。之前未提交的其他功能改动不归为本轮新增修复。
