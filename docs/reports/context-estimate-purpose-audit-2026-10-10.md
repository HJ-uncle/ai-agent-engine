## 20% 安全余量拆解

代码位置：`src/core/agent-loop/finalization.ts:35` 的 `estimateRequestInput`，`src/core/utils/model-context.ts:28` 的 `estimateModelMessageTokens`，`src/core/utils/tokens.ts:9` 的 `estimateTokens`。

ReAct 预估由历史逐条估算加系统提示词与工具定义估算组成。每条历史消息取 `ceil(基础估算 × 1.2)`，系统与工具整体也取 `ceil(基础估算 × 1.2)`；这是安全容量，不是计费量。

| 组成 | seq 386 | seq 458 |
|---|---:|---:|
| 历史基础估算 | 75,885 | 67,522 |
| 历史加入 20% 及逐条取整后 | 91,164 | 81,136 |
| 历史增加的安全余量 | 15,279 | 13,614 |
| 系统与工具含安全余量的贡献 | 19,803 | 19,803 |
| ReAct 完整预估 | **110,967** | **100,939** |
| 最终模型统计输入 | **91,754** | **87,295** |

历史组成由 JSONL 按当时追加顺序重放更新、投影和工具配对后实算。原请求系统提示词与工具定义未完整持久化，`19,803` 是保存的完整预估减历史估算得到的固定贡献，不能作为原文重建或某个工具的精确费用。

该固定贡献满足 `ceil(整数基础估算 × 1.2) = 19,803`，唯一整数基础估算为 `16,502`。因此可得：

| 算术分离安全余量 | seq 386 | seq 458 |
|---|---:|---:|
| 历史基础 + 系统工具基础 | 92,387 | 84,024 |
| 完整估算额外预留 | 18,580 | 16,915 |
| 基础估算减模型统计 | +633 | −3,271 |

这是对本次算法的成分拆解，不是建议直接把预估除以 1.2 冒充精准 token 数；图片、字符分词差异以及每条消息的取整仍然存在。

## 字符、图片及工具估算

`estimateTokens` 的普通文本规则是汉字 `1.5 token/字符`、其他 UTF-16 字符 `0.25 token/字符`，最后向上取整。它不执行 DeepSeek tokenizer。代码、英文、中文和标点的真实分词比例随模型和内容变化；重复内容、随机字符串和不同语言也不能共用精确比例。

`src/core/utils/multimodal-context.ts` 对原生图片按语义估算，不把图片 base64 字节当成文本再计数。低清图预留 `512`；PNG/GIF 可读尺寸时按 `ceil(width × height / 256) + 512`、下限 `512`、上限 `16384`；未取得廉价尺寸的 JPEG/WebP/远程图默认 `8192`，再加块结构余量。以上是保守额度，不是 DeepSeek/Anthropic 所有视觉模型的实际图像 token 公式。本次转译后的 seq 386/458 历史仍分别有 3/2 张原生图片；本审计不据此推断网关内部视觉分词行为。

长 dense/base64/minified 文本另有保护：满足标记或密集段条件时，密集字符按 `0.75` 系数估算，避免大量随机字符被普通 `0.25` 系数严重低估。不能为了让 UI 数值看起来接近而取消该保护。

工具定义用 JSON 结构和字符估算，包含名称、描述和 schema。JSON 字符估计并不等于上游实际提示词编码中的协议开销。

## ReAct 显示值与出站准入值

`src/core/llm-adapter/request-attempt.ts:7` 的 `prepareRequestContext` 使用：

```text
出站输入安全估算 = max(ReAct requestInputTokenEstimate, estimateProviderRequestInput(转译后请求))
输出上限 = min(协议输出上限, 配置窗口 - 出站输入安全估算)
```

`estimateProviderRequestInput` 位于 `src/core/utils/multimodal-context.ts`，对实际协议请求的系统、工具和消息进行估算，同样含 1.2 安全系数。它不计温度、模型名称或 max_tokens 等非输入配置。

当前诊断字段 `requestInputTokenEstimate` 保存和发布的是 ReAct 预估；适配器为了预算安全可再提高出站估算并缩小输出容量，但该值未回填为 ReAct 的诊断字段。原完整系统与工具请求没有落库，因此本次只精确重放历史转译差异，不能声称恢复了旧请求的完整出站数字。

## 本轮产品决策及改进边界

本轮只由客户端去除常驻的预估数字与相关空白，避免让上一请求确认值和下一请求安全估算看起来必须同步。保留诊断字段、原始模型统计、20% 预算保护和自动压缩行为；未改引擎估算算法，也未修改真实计费。

后续若需要展示预请求预测，应分别命名基础输入预测、安全容量与已确认输入，并以同一次实际转译后的请求为共同来源。若要在发送前获得精确模型 token 数，需要所选网关支持该模型的 `count_tokens` 接口或准确匹配的 tokenizer；当前适配器 `countTokens` 仍调用字符估算，不能通过调整比例保证所有模型、图片、工具和任意长历史精确。

本轮没有引擎源码变更，因此不重复运行此前已通过的 539 条回归或构建。最终客户端类型、构建与操作测试已由本轮主任务完成，结果如下。
