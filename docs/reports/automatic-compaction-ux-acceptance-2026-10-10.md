# 自动上下文压缩交互验收记录

日期：2026-10-10。涉及引擎 `D:\dev\ai-agent-engine` 与主客户端 `D:\dev\aether-code`。

## 用户可见行为

- 删除手动压缩按钮、点击用量环触发压缩、手动 HTTP 接口，以及 SDK 和旧 Web 控制台的对应入口。
- 自动压缩实际开始时，消息末尾原“执行命令…”提示优先显示“正在自动压缩上下文…”。消息运行状态同步显示该文案，包含任务完成后仍在执行的后台压缩。
- 用量环显示忙碌动画，悬浮用量卡片显示“压缩中…”与不定进度。没有可计算的压缩百分比，因此不显示虚构百分比。
- 成功或失败后，环和卡片短暂显示结果；消息末尾恢复原执行或生成状态。失败保留原历史。
- 每条消息使用自己的 RootRun 压缩状态，避免历史消息和其他会话串状态。断线重连、快照恢复也能恢复正在压缩的提示。
- 压缩前后数字标为“历史估算”，不覆盖已确认的模型请求输入用量；后续真实模型请求确认后更新上下文占用。

## 根因与实现

此前压缩流程缺少可持久化、可通过 SSE 和快照恢复的状态，客户端消息提示主要依赖工具运行状态。请求结束后的压缩还可能在 SSE 关闭后执行，用户只能看到旧工具提示。

现在压缩流程发布 `running / succeeded / failed` 状态并持久化至 RootRun，经现有 `__run__` SSE 推送。实际摘要请求前通知开始，历史提交成功后通知完成；无须摘要的清理不会假报压缩。请求结束后的压缩在 producer 关闭前等待完成。

摘要请求优先使用当前会话实际解析的模型配置，包括 endpoint、provider、headers 和凭据。恢复时使用最近任务的模型配置，凭据从租户模型库解密；专职摘要模型使用自己的租户配置。任务完成时间与压缩完成时间分别保存，压缩维护更新不会改写已完成任务的完成时间。

压缩期间缓存原历史与用量快照，恢复不等待历史锁。子 Agent 恢复严格使用已发布事件的状态和用量，避免投影淘汰导致遗漏或提前显示尚未发布的数据。
