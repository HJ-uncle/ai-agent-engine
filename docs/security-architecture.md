# 安全策略与运行边界

本文描述 2026-11-17 的服务端实现。账号登录、恢复与提权见 [账号指南](account-login.md)；本文聚焦工具执行、工作区、网络、批准和审计。这里的“沙盒”不是对所有宿主进程提供操作系统级隔离的承诺。

## 安全链路

请求身份与租户 → 会话/工作区绑定 → 工具模式及授权能力 → 可信工具策略 → 批准或拒绝 → 实际文件/命令/网络操作 → 审计与可恢复记录。

认证角色来自可信身份，不能由聊天文字或普通自定义请求头提升。工具包与 allowedTools 决定哪些能力可被注册；注册成功也不免除资源范围、参数、批准和运行状态检查。子代理继承可信租户、父会话和工作区边界，不能继承主代理的配置管理工具包。

## 三种安全模式

默认是 `standard`；`DEFAULT_SECURITY_MODE` 有非法值时回退 `safe`。会话覆盖和已批准命令当前由内存 Map/Set 保存，不能承诺重启后继续存在。

| 检查 | safe | standard | full-access |
| --- | --- | --- | --- |
| 普通 allow 规则 | 放行 | 放行 | 放行 |
| 普通 ask 规则 | 请求批准 | 放行 | 放行 |
| 普通 deny 规则 | 拒绝 | 请求批准 | 放行 |
| 删除命令硬拦截 | 拒绝，要求记录式删除工具 | 同左 | 同左 |
| 身份、资源、参数等硬边界 | 保留 | 保留 | 保留 |

[policy-engine.ts](../src/security/policy-engine.ts) 的执行顺序比旧注释中的“跳过所有检查”更准确。删除命令与若干内联删除模式在已批准命令和 full-access 放行前检查；这是静态防护，不等同识别任意脚本的所有副作用。safe 对解释器要求批准；注入特征通常拒绝，特定后台解释器启动可转批准。standard 对注入特征要求批准。

安全模式是审批策略，不是文件系统权限本身。解释器、包管理器、外部程序可能访问工作目录之外的宿主资源；生产隔离需要按部署环境另行建立操作系统、容器或账户权限边界。

## 文件与批准

文件工具解析实际路径并检查工作区范围；删除走可追踪变更管线。回退还需要检查当前哈希、后续改动、明确审阅的命令观察记录及目录归属，不能把回退描述成对任意 shell 副作用的事务撤销。

等待批准的操作使用已持久化的冻结参数及身份。后续消息、会话工具包变更或重试不能重新解释同一批准对象。full-access 仍保留真正向用户收集信息的提问。

安全模式修改接口在 [security.ts](../src/api/http/routes/security.ts) 校验 admin/tenant-admin；远端 full-access 进一步要求 admin，桌面 loopback instance-token 路径有专用可信例外。前端隐藏按钮不构成授权检查。

## 网络

[network-policy.ts](../src/security/network-policy.ts) 默认允许 HTTP/HTTPS，禁止私有地址并阻断元数据端点；默认响应上限 5 MiB、超时 30 秒、DNS 缓存 300 秒。[guarded-http.ts](../src/security/guarded-http.ts) 对重定向逐跳检查、最多 5 跳，固定已检查 DNS 目标，拒绝 URL 内嵌凭据并限制响应。

这些保证适用于使用 guarded HTTP 的路径，不自动覆盖所有模型 SDK、MCP 服务、浏览器、宿主命令或第三方插件的网络访问。full-access 的网络策略也有专门处理，不能把默认限制直接推广到所有模式。

## 审计与维护

策略与工具路径按实现写入审计；日志正文可外置压缩。审计管理接口校验管理员权限；清理流程保留归档，不应把 UI 清空等同物理无痕删除。操作日志、token 使用和 QA 日志是不同数据，详见 [运行指南](runtime-guide.md) 与 [存储维护](operations/session-storage-maintenance.md)。

本次仅核对源码，未重新做渗透、容器逃逸或所有外部工具的端到端安全测试。主要验证入口为 [安全测试](../src/security/__tests__/)、[工具注册测试](../src/tools/__tests__/) 和 [HTTP 路由测试](../src/api/http/routes/__tests__/)。
